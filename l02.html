Parameters vs Hyperparameters ⭐

Parameters are the internal gears that adjust automatically during training. Hyperparameters are the external dials that you set before training. The algorithm cannot adjust these on its own.

TypeAdjusted ByWhenExample
ParameterThe model (automatically)During trainingWeights $(w_1, w_2)$, Intercept $(w_0)$
HyperparameterThe engineer (manually)Before trainingmax_depth, n_estimators, learning_rate

Common production hyperparameters

  • Decision Trees: max_depth — maximum splits allowed. Too low = too simple; too high = data memorize kar lega.
  • Random Forests: n_estimators — how many trees to build in the ensemble.
  • Gradient Descent: learning_rate — the step size toward minimum error. Too large = overshoot; too small = never converges.

Hyperparameter tuning is an iterative process: run multiple training cycles with different configurations, check the score against the validation data, and find the optimal combination.

Practice P1

Classify: Parameter [P] or Hyperparameter [H]?

ItemAnswerWhy
(a) Weight $w_1$ in a regression equationPLearned by gradient descent during training.
(b) max_depth of a Decision TreeHYou set it before calling fit().
(c) Intercept $w_0$ in $y = w_0 + w_1x_1$PThe bias term is a learned parameter too.
(d) learning_rate for Gradient DescentHThe algorithm cannot optimise this for itself.
(e) n_estimators in a Random ForestHAn architecture choice — fixed before training.
(f) Bias term learned during backpropagationP"Learned during" = parameter, by definition.

5Data Splitting (The Golden Barrier)

▷ Hook

If a student memorises last year's exam answers and scores 100%, does that prove they understood the subject? If your ML model scores 100% on data it has already seen, does it actually know how to predict the future?

Parameters need training data, hyperparameters need validation data, and the final grade needs untouched test data. Three blocks:

△ Senior Engineer's Warning — DATA LEAKAGE

Data splitting must happen BEFORE feature engineering. If you scale or impute on the whole dataset, information from the validation and test sets leaks into training. That gives you artificially high scores but catastrophic failure on genuinely unseen production data.

★ Key Insight

If you peeked at the test data during development, you leaked the exam answers — and your final performance metrics are permanently compromised.

Practice P2

Fill in the blanks & True/False

  1. (a) The ______ set is locked away until the very end to give an unbiased final grade.
    Test
  2. (b) You should calculate the mean of the ENTIRE dataset before splitting to replace missing values. [T/F]
    False — this is classic data leakage. Compute the mean from the training set only.
  3. (c) Which set is used to tune Hyperparameters?
    Validation
  4. (d) Peeking at the test set during development invalidates your evaluation. [T/F]
    True
△ Reflect 1 — Is this leakage?

A data scientist computes the mean salary from ALL 100,000 rows, then splits, and uses that mean to impute missing values in the training set. Is this leakage?
Yes, definitely. That mean carries information from the test-set rows — meaning the test set influenced the training process. The test score is now artificially optimistic, because the model indirectly learned something about the test distribution. The right way: split first, compute the mean from training rows only, and apply that same mean to train, val and test.

♦ Takeaway

Split FIRST, engineer SECOND. The test set is sacred — touch it only once, right at the very end.

6Feature Engineering (Crafting Perspective)

▷ Hook

Think about predicting exam scores. The night before, one student studies 10 hours but sleeps 0 — they fail. Another sleeps 10 hours but studies 0 — they also fail. Success depends on the combination of study AND sleep, not on either one alone. Can an algorithm figure that out if it looks at each column separately?

Raw data is like raw marble. Feature engineering is the carving that makes the underlying structure obvious. It has two operational pillars:

Pillar 1 · Feature Creation

Generating entirely new inputs from existing ones, so that hidden relationships get exposed.

  • Leveraging domain knowledge: using industry expertise to turn raw values into meaningful concepts.
    • Example: instead of processing the raw temperature (41°C), group it using meteorological thresholds: Cold ($\le 15°$C), Warm ($16$–$30°$C), Hot ($>30°$C).
    • This reduces infinite decimal noise into meaningful categories the model can actually exploit.
  • Combining Features: mathematically combining columns to capture joint effects.
    • Example: Water_Availability_Index = Average_Rainfall_Inches × Soil_Moisture_Percentage
    • This single calculated value hands the combined effect straight to the model.

Pillar 2 · Feature Selection

If you throw 500 features at an algorithm and many of them are useless noise, the model gets confused and overfits. Feature selection keeps the highly predictive inputs and discards the rest.

Filter Methods

Screening features with simple statistical metrics (e.g. correlation) before any training. If a feature's correlation with the target is $\approx 0$, filter it out.

Embedded Methods

Feature selection happens automatically during training. Tree-based models (Random Forests) compute internal feature importance scores. L1 (Lasso) regularization is embedded too.

Wrapper Methods

Training the actual model on different feature subsets to see which subset performs best. (👉 in detail in Lecture 10)

★ Key Insight

If your features are high quality, even a simple algorithm gives highly accurate predictions. If the features are poor, even the most complex neural network will struggle.

7Baseline Establishment (The Performance Floor)

Before you write a single line of a complex model, you have to answer: what counts as a "good" prediction? A baseline is the simplest possible model — often a historical average, a majority-class guess, or a primitive linear model.

Technical benchmark

If a more complex ML model cannot beat a simple baseline (historical average or majority class), then the extra complexity is not justified.

Business benchmark

Is a 2% accuracy increase worth spending millions more on cloud infrastructure, training time and maintenance?

Practice P4

Cost–Benefit Analysis

A Decision Tree classifier achieves 80% accuracy. A Random Forest gives 81% accuracy, but needs significantly more computation and costs ₹20 lakh extra to deploy.

  1. (a) Is a 1% improvement necessarily worth it?
    No — not in the general case.

    But this is domain-dependent. A 1% gain for ₹20 lakh is a waste in e-commerce recommendations. But if this is cancer screening, and 1% means 100 extra correct diagnoses in 10,000 patients — then it is absolutely worth it. Always translate accuracy into business value.

  2. (b) Why is it essential to compare against a baseline before selecting a complex model?

    Because without a baseline you have no definition of "good" at all. 81% accuracy looks impressive — until you find out that a majority-class guess already gives 79%. A baseline sets a performance floor; the higher that floor, the weaker the justification for complexity.

♦ Takeaway

The baseline sets a performance floor. If a complex model cannot beat it, the extra cost and complexity are wasted.

8The Modeling Loop (Select, Tune & Train)

In production, selecting an algorithm, setting its dials and updating its maths do not happen linearly — they run together in one iterative, experimental loop.

Pillar A · Model Selection (Picking the Right Tool)

▷ Hook

A hospital needs to predict heart attacks. One model is 85% accurate and explains its reasoning step by step. Another is 92% accurate but a total black box. When a wrong prediction can be fatal, which one do you choose?

Model selection is never about blindly picking the "most powerful" algorithm. It is an exercise in engineering trade-offs.

Decision FactorWhat it MeansTrade-off
InterpretabilityCan the model explain its reasoning?Higher → easier to audit, but often lower accuracy
AccuracyHow correct are the predictions?Higher → better predictions, but can be a black box
Training TimeHow long does it take to train?Complex models take hours or days on large data
ScalabilityCan it handle millions of rows?Simple models scale easily; deep learning needs GPUs

Mapping to core computational tasks

TaskGoalAlgorithm Examples
RegressionPredict a continuous valueLinear Regression, Random Forest Regressor
ClassificationPredict a discrete labelLogistic Regression, SVM, Decision Trees
ClusteringUncover unlabelled structuresK-Means, DBSCAN
Practice P5

Hospital case study — interpretability vs accuracy

Hospital chooses: A (85% accurate but explainable).

Reasoning: In medicine, the doctor has to audit the model's reasoning — they carry the legal and ethical responsibility for the patient. A black-box "high risk" output that cannot be justified is neither clinically actionable nor legally defensible. Liability, informed consent and regulatory compliance all demand traceable reasoning. Better to give up 7% accuracy than deploy a system nobody can challenge or debug.

Self-driving car company: B (92% accurate black-box).

Does the answer change? Yes. Here decisions happen in milliseconds — no human is reviewing an explanation in real time. The metric that matters is aggregate safety: 92% accuracy means statistically fewer crashes. Explaining each individual braking decision has no practical value as long as the fleet-level outcome is better. And that is the real lesson: there is no universal answer to "interpretability vs accuracy" — it depends entirely on whether the decision needs human review.

Pillar B · Model Training (The Engine Room)

Model training is the core phase where the algorithm converts data into automated knowledge. The model reviews the training data, calculates its own errors, and updates its internal parameters.

Concrete example — Multiple Linear Regression

A model predicts crop yield from rainfall and soil moisture:

Model$$y = w_0 + w_1x_1 + w_2x_2$$
  • $y$ = predicted output (Crop Yield)
  • $x_1, x_2$ = input features (Rainfall, Soil Moisture)
  • $w_1, w_2$ = weights (how much influence each feature has)
  • $w_0$ = the intercept (the baseline when all inputs are zero)

The weights $(w_1, w_2)$ and the intercept $(w_0)$ are the internal parameters. Training finds the exact numerical values that give the most accurate predictions.

The Measuring Stick: The Loss Function (MSE)

A loss function (or cost function) computes a single score telling you how far the predictions are from the true values:

Mean Squared Error$$\text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat y_i)^2$$
  • $n$ = total number of data points
  • $y_i$ = actual true value from dataset
  • $\hat y_i$ = model's predicted value
  • We square the error so that negatives don't cancel positives. Goal: $\text{MSE} \to 0$.
Related

$\text{RMSE} = \sqrt{\text{MSE}}$ — this brings the error back into the target's original units.

Numerical

Compute MSE and RMSE by hand

Actual $y = [10,\ 12,\ 13]$  ·  Predicted $\hat y = [9,\ 15,\ 13]$

  1. Find the error for each point
    $i$$y_i$$\hat y_i$$y_i - \hat y_i$$(y_i-\hat y_i)^2$
    1109+11
    21215−39
    3131300
    Sum of squared errors10
  2. Apply the MSE formula $$\text{MSE} = \frac{1}{n}\sum (y_i - \hat y_i)^2 = \frac{10}{3} = \mathbf{3.33}$$
  3. Find the RMSE $$\text{RMSE} = \sqrt{3.33} = \mathbf{1.826}$$
  4. Interpret it
    The average squared miss is 3.33 (units²); in original units the typical miss is ≈ 1.83. Point 2 (error −3) alone contributes $9/10 = 90\%$ of the MSE — that is exactly what squaring does.
Trap to remember

If one prediction were $\hat y = 50$ while $y=13$, that single error would square to $(37)^2 = 1369$ — crushing every other error. This is why MSE is so sensitive to outliers.

Optimization via Gradient Descent

Mountain analogy: Imagine standing on a mountain in thick fog. You feel the slope under your feet and take one step downhill. Repeat until the ground is flat. Altitude = loss value. Your coordinates = model weights. Gradient descent computes the mathematical slope and adjusts the weights towards the lowest error.

Convergence: As the algorithm approaches the bottom of the error valley, the slope approaches zero. The steps become tiny. The loss flattens out. Training completes and the parameters lock in.

The step-by-step training loop ⭐

StepActionWhat Happens
1InitializeSet random parameter values — the weights start from random numbers
2Forward PassMake predictions: $\hat y = w_0 + w_1x_1 + w_2x_2$
3Compute LossMeasure the error (MSE) — how far are the predictions from the truth?
4Backward PassGradient Descent — calculate the slope; adjust the weights downhill
5Convergence?Check whether the loss is stable. Flat → stop. Not flat → repeat from Step 2

9Offline Evaluation (The Final Exam)

Once the model has trained and converged, it is time for the final exam. We pass the untouched test set through the locked model.

1. Technical evaluation metrics for Regression

MetricWhat It DoesBest For
MAE
Mean Absolute Error
$\frac{1}{n}\sum|y_i - \hat y_i|$		The average of $|$True − Predicted$|$. Treats all errors linearly.Interpretable for non-technical stakeholders. An MAE of 5.2 = on average 5.2 units off.
RMSE
Root Mean Squared Error
$\sqrt{\frac1n\sum(y_i-\hat y_i)^2}$		The square root of the average squared error. Heavily penalises large errors.When large errors are catastrophic. 9 small errors + 1 huge one → RMSE spikes.
$R^2$ Score
Coefficient of Determination		A relative scale from 0 to 1. Compares the model against a baseline average guess.0.85 = the model explains 85% of the variance. Shows improvement over the baseline directly.

📌 $R^2$ is covered in detail in Lecture 7.

2. Business metric mapping

In the software industry you have to translate mathematical performance into business value. Engineers must map technical results directly onto operational impact.

Example

In agriculture, reducing RMSE by 1.5 units → a 12% reduction in predicted crop failure → saves an estimated ₹2,00,000 per field hectare in lost revenue.

Practice P7

Pick the right metric

ScenarioMetricWhy
(a) A medical prediction error of 100 units is catastrophic (fatal)RMSESquaring punishes large errors disproportionately — exactly the behaviour you want when one big miss is fatal.
(b) A non-technical CEO asks "how much better is this model than random guessing?"$R^2$$R^2$ is a relative score against the mean-only baseline — a direct answer to "how much better".
(c) A logistics team wants "on average, how many km off are our delivery estimates?"MAE"On average, how many units off" is literally the definition of MAE, and it reads in the original units.
△ Reflect 2

Why is improving RMSE by 1.5 units valuable to an agricultural business?
Because yield prediction drives all the downstream planning: how much fertiliser to buy, how many storage silos to book, what price to sign forward contracts at. Even a small prediction error translates into over-purchasing, spoilage or missed contracts. A 1.5-unit RMSE reduction directly cuts predicted crop failure by 12%, which saves ₹2,00,000 per hectare. This is not an abstract statistical improvement — it shows up on the balance sheet.

♦ Takeaway

MAE for an equal-penalty interpretation. RMSE when large errors are catastrophic. $R^2$ for relative performance against a baseline. Always translate the metric into business value.

10Model Deployment (Into the Wild)

▷ Hook

You spent months building an accurate model. It runs perfectly on your laptop. But the customer cannot access your terminal. How do you make this mathematical asset usable for thousands of everyday customers?

A model sitting on a laptop is useless to a business. Deployment packages the trained parameters into accessible formats and embeds them in production infrastructure.

Serialise the model, choose the right pathway (API, Cloud, Edge), and pick Batch vs Real-Time based on latency needs.

11Post-Deployment (The Living System)

▷ Hook

You deploy an ML model in 2019 to predict airline travel. In 2020 a global pandemic arrives. Your model was trained on 2010–2019 data. Is it still accurate?

Model Drift

Traditional code runs identically forever. ML models decay. Model drift happens when prediction accuracy falls because the real-world environment has changed, leaving the original training insights outdated.

Continuous production monitoring

  • Tools like Prometheus and MLflow run continuously in the background.
  • They track the statistical distributions of incoming live data.
  • The moment performance falls below an acceptable baseline threshold, they alert the engineering team.

The retraining cycle

StrategyHow It WorksExample
Periodic RetrainingA fixed schedule (monthly/quarterly), regardless of performanceAutomatically retrain on the 1st of every month
Triggered RetrainingStarts when monitoring detects accuracy below a thresholdAlert: accuracy dropped below 85% → retrain now

A model is not a static script. It is a living mathematical system that has to adapt to a changing world through monitoring and retraining.
