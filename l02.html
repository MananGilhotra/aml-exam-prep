Parameters vs Hyperparameters ⭐

Parameters wo internal gears hain jo training ke dauraan automatically adjust hote hain. Hyperparameters wo external dials hain jo tum training se pehle set karte ho. Algorithm inhe apne aap adjust nahi kar sakta.

TypeAdjusted ByWhenExample
ParameterThe model (automatically)During trainingWeights $(w_1, w_2)$, Intercept $(w_0)$
HyperparameterThe engineer (manually)Before trainingmax_depth, n_estimators, learning_rate

Common production hyperparameters

  • Decision Trees: max_depth — maximum splits allowed. Too low = too simple; too high = data memorize kar lega.
  • Random Forests: n_estimators — ensemble mein kitne trees banane hain.
  • Gradient Descent: learning_rate — minimum error ki taraf step size. Too large = overshoot; too small = kabhi converge nahi.

Hyperparameter Tuning ek iterative process hai: alag-alag configurations ke saath multiple training cycles chalao, score ko Validation Data ke against check karo, aur optimal combination dhoondo.

5Data Splitting (The Golden Barrier)

▷ Hook

Agar ek student pichle saal ke exam ke answers ratt le aur 100% le aaye — kya isse prove hota hai ki usne subject samjha? Agar tumhara ML model us data par 100% score kare jo usne pehle dekh liya hai, kya wo actually future predict karna jaanta hai?

Parameters ko training data chahiye, hyperparameters ko validation data chahiye, aur final grade ke liye untouched test data chahiye. Teen blocks:

△ Senior Engineer's Warning — DATA LEAKAGE

Data splitting Feature Engineering se PEHLE honi chahiye. Agar tum poore dataset par scale ya impute karte ho, to validation aur test sets ki information training mein leak ho jaati hai. Isse artificially high scores milte hain par truly unseen production data par catastrophic failure hota hai.

★ Key Insight

Agar tumne development ke dauraan test data par peek kiya (prematurely dekha), to tumne exam ke answers leak kar diye — aur tumhare final performance metrics hamesha ke liye compromised ho gaye.

△ Reflect 1 — Is this leakage?

Ek data scientist SAARI 100,000 rows se mean salary compute karta hai, phir split karta hai, aur us mean se training set ke missing values impute karta hai. Leakage hai?
Haan, definitely. Us mean mein test set ki rows ki information baithi hai. Yaani test set ne training process ko influence kiya. Ab test score artificially optimistic hai kyunki model ko indirectly test distribution ke baare mein pata chal gaya. Sahi tareeka: pehle split, phir sirf training rows se mean nikaalo, aur wahi mean train + val + test teeno par apply karo.

♦ Takeaway

Split FIRST, engineer SECOND. Test Set pavitra hai — use sirf ek baar, bilkul aakhir mein chhuo.

6Feature Engineering (Crafting Perspective)

▷ Hook

Exam scores predict karne ki socho. Exam se ek raat pehle, ek student 10 hours padhta hai par 0 hours sota hai — wo fail ho jaata hai. Doosra 10 hours sota hai par 0 hours padhta hai — wo bhi fail. Success study AND sleep ke combination par depend karta hai, akele kisi ek par nahi. Kya algorithm yeh figure out kar sakta hai agar wo har column ko alag-alag dekhe?

Raw data raw marble ki tarah hai. Feature Engineering use tarashna hai taaki underlying structure obvious ho jaye. Iske do operational pillars hain:

Pillar 1 · Feature Creation

Existing inputs se bilkul naye inputs generate karna taaki hidden relationships expose ho.

  • Leveraging Domain Knowledge: Industry expertise se raw values ko meaningful concepts mein badalna.
    • Example: Raw temperature (41°C) process karne ki jagah, meteorological thresholds use karke group karo: Cold ($\le 15°$C), Warm ($16$–$30°$C), Hot ($>30°$C).
    • Isse infinite decimal noise meaningful categories mein reduce ho jaata hai jinhe model exploit kar sakta hai.
  • Combining Features: Columns ko mathematically combine karke joint effects capture karna.
    • Example: Water_Availability_Index = Average_Rainfall_Inches × Soil_Moisture_Percentage
    • Yeh ek calculated value combined effect ko directly model tak pahuchati hai.

Pillar 2 · Feature Selection

Agar tum 500 features algorithm par phenk do, jinme se kai useless noise hain, to model confuse hoga aur overfit karega. Feature selection highly predictive inputs rakhta hai aur baaki discard karta hai.

Filter Methods

Training se pehle statistical metrics (e.g. correlation) se features screen karna. Agar feature ki target ke saath correlation $\approx 0$, filter it out.

Embedded Methods

Feature selection training ke dauraan automatically hota hai. Tree-based models (Random Forests) internal Feature Importance Scores calculate karte hain. L1 (Lasso) Regularization bhi embedded hai.

Wrapper Methods

Actual model ko alag-alag feature subsets par train karke dekhna ki konsa subset best perform karta hai. (👉 detail in Lecture 10)

★ Key Insight

Agar tumhare features high quality hain, to ek simple algorithm bhi highly accurate predictions deta hai. Agar features poor hain, to sabse complex neural network bhi struggle karega.

7Baseline Establishment (The Performance Floor)

Complex model ka code likhne se pehle tumhe answer dena hoga: "Good prediction" kya hota hai? Ek baseline sabse simple possible model hai — often ek historical average, majority class guess, ya primitive linear model.

Technical benchmark

Agar ek zyada complex ML model simple baseline (historical average ya majority class) ko beat nahi kar sakta, to extra complexity justified nahi hai.

Business benchmark

Kya 2% accuracy increase cloud infrastructure, training time aur maintenance par millions zyada kharch karne layak hai?

Practice P4

Cost–Benefit Analysis

Ek Decision Tree classifier 80% accuracy achieve karta hai. Ek Random Forest 81% accuracy deta hai, par significantly zyada computation chahiye aur deploy karne mein ₹20 lakh extra lagte hain.

  1. (a) Kya 1% improvement zaroori hai worth it?
    No — general case mein nahi.

    Lekin yeh domain-dependent hai. ₹20 lakh ke liye 1% gain e-commerce recommendation mein waste hai. Par agar yeh cancer screening ho aur 1% ka matlab 10,000 patients mein 100 extra correct diagnoses ho — to bilkul worth it hai. Hamesha accuracy ko business value mein translate karo.

  2. (b) Complex model select karne se pehle baseline se compare karna kyun zaroori hai?

    Kyunki baseline ke bina tumhare paas "good" ki koi definition hi nahi. 81% accuracy impressive lagti hai — jab tak tumhe pata na chale ki majority-class guess bhi 79% de deta. Baseline ek performance floor set karta hai; wo floor jitna upar hoga, complexity ka justification utna kamzor.

♦ Takeaway

Baseline performance floor set karta hai. Agar complex model use beat nahi kar sakta, to extra cost aur complexity waste hai.

8The Modeling Loop (Select, Tune & Train)

Production mein algorithm select karna, uske dials set karna, aur uska maths update karna linearly nahi hota — yeh ek iterative, experimental loop mein saath chalte hain.

Pillar A · Model Selection (Picking the Right Tool)

▷ Hook

Ek hospital ko heart attacks predict karne hain. Ek 85% accurate model apni reasoning step-by-step explain karta hai. Ek 92% accurate model total black-box hai. Jab ek galat prediction fatal ho sakti hai, tum kaunsa choose karoge?

Model selection kabhi bhi blindly "most powerful" algorithm pick karna nahi hai. Yeh engineering trade-offs ka exercise hai.

Decision FactorWhat it MeansTrade-off
InterpretabilityKya model apni reasoning explain kar sakta hai?Higher → audit karna easy, par often lower accuracy
AccuracyPredictions kitni correct hain?Higher → better predictions, par black-box ho sakta hai
Training TimeTrain hone mein kitna time?Complex models large data par hours/days lete hain
ScalabilityKya millions of rows handle kar sakta hai?Simple models easily scale; deep learning ko GPUs chahiye

Mapping to core computational tasks

TaskGoalAlgorithm Examples
RegressionPredict a continuous valueLinear Regression, Random Forest Regressor
ClassificationPredict a discrete labelLogistic Regression, SVM, Decision Trees
ClusteringUncover unlabelled structuresK-Means, DBSCAN
Practice P5

Hospital case study — interpretability vs accuracy

Hospital chooses: A (85% accurate but explainable).

Reasoning: Medicine mein doctor ko model ki reasoning audit karni padti hai — wo patient par legal aur ethical responsibility leta hai. Ek black-box "high risk" output jise justify nahi kiya ja sakta, na hi clinically actionable hai aur na hi legally defensible. Liability, informed consent aur regulatory compliance sab traceable reasoning demand karte hain. 7% accuracy ka nuksaan uthana better hai bajaye ek aise system ke jise koi challenge ya debug hi na kar sake.

Self-driving car company: B (92% accurate black-box).

Kya answer badalta hai? Haan. Yahan decisions milliseconds mein leni hoti hain — koi human real-time mein explanation review nahi kar raha. Metric jo matter karta hai wo hai aggregate safety: 92% accuracy ka matlab statistically kam crashes. Har individual braking decision explain karne ki koi practical value nahi jab tak fleet-level outcome better ho. Yehi asli lesson hai: "interpretability vs accuracy" ka koi universal answer nahi — yeh puri tarah se is baat par depend karta hai ki decision ko human review chahiye ya nahi.

Pillar B · Model Training (The Engine Room)

Model Training core phase hai jahan algorithm data ko automated knowledge mein convert karta hai. Model training data review karta hai, apne errors calculate karta hai, aur apne internal parameters update karta hai.

Concrete example — Multiple Linear Regression

Ek model rainfall aur soil moisture se crop yield predict karta hai:

Model$$y = w_0 + w_1x_1 + w_2x_2$$
  • $y$ = predicted output (Crop Yield)
  • $x_1, x_2$ = input features (Rainfall, Soil Moisture)
  • $w_1, w_2$ = weights (har feature ka kitna influence hai)
  • $w_0$ = intercept (baseline jab saare inputs zero hon)

Weights $(w_1, w_2)$ aur intercept $(w_0)$ hi internal parameters hain. Training exact numerical values dhoondti hai jo sabse accurate predictions dein.

The Measuring Stick: The Loss Function (MSE)

Ek Loss Function (ya Cost Function) ek single score calculate karta hai jo batata hai ki predictions true values se kitni door hain:

Mean Squared Error$$\text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat y_i)^2$$
  • $n$ = total number of data points
  • $y_i$ = actual true value from dataset
  • $\hat y_i$ = model's predicted value
  • Hum error ko square karte hain taaki negatives positives ko cancel na karein. Goal: $\text{MSE} \to 0$.
Related

$\text{RMSE} = \sqrt{\text{MSE}}$ — yeh error ko wapas target ki original units mein le aata hai.

Numerical

Compute MSE and RMSE by hand

Actual $y = [10,\ 12,\ 13]$  ·  Predicted $\hat y = [9,\ 15,\ 13]$

  1. Har point ka error nikalo

    Sum of squared errors10
  2. MSE formula apply karo $$\text{MSE} = \frac{1}{n}\sum (y_i - \hat y_i)^2 = \frac{10}{3} = \mathbf{3.33}$$
  3. RMSE nikalo $$\text{RMSE} = \sqrt{3.33} = \mathbf{1.826}$$
  4. Interpret karo
    Average squared miss 3.33 (units²) hai; original units mein typical miss ≈ 1.83 units. Point 2 (error −3) poore MSE mein $9/10 = 90\%$ contribute kar raha hai — yahi squaring ka effect hai.
Trap to remember

Agar ek prediction $\hat y = 50$ hoti jabki $y=13$, to us akele error ka square $(37)^2 = 1369$ hota — baaki sab errors ko crush kar deta. Isiliye MSE outliers ke prati bohot sensitive hai.

Optimization via Gradient Descent

Mountain analogy: Socho tum ek pahaad par ghane kohre mein khade ho. Tum apne pairon ke neeche ka slope mehsoos karte ho aur dhalaan ki taraf ek step lete ho. Repeat karo jab tak zameen flat na ho jaye. Altitude = Loss Value. Tumhare coordinates = Model Weights. Gradient descent mathematical slope calculate karta hai aur weights ko lowest error ki taraf adjust karta hai.

Convergence: Jaise-jaise algorithm error valley ke bottom ke paas aata hai, slope zero ke paas pahuchta hai. Steps tiny ho jaate hain. Loss flatten ho jaati hai. Training complete hoti hai aur parameters lock ho jaate hain.

The step-by-step training loop ⭐

StepActionWhat Happens
1InitializeRandom parameter values set karo — weights random numbers se start
2Forward PassPredictions banao: $\hat y = w_0 + w_1x_1 + w_2x_2$
3Compute LossError measure karo (MSE) — predictions truth se kitni door hain?
4Backward PassGradient Descent — slope calculate karo; weights downhill adjust karo
5Convergence?Check karo loss stable hai kya. Flat → stop. Nahi → Step 2 se repeat

9Offline Evaluation (The Final Exam)

Jab model train aur converge ho jaata hai, final exam ka time hai. Hum untouched Test Set ko locked model ke through pass karte hain.

1. Technical evaluation metrics for Regression

MetricWhat It DoesBest For
MAE
Mean Absolute Error
$\frac{1}{n}\sum|y_i - \hat y_i|$		$|$True − Predicted$|$ ka average. Saare errors ko linearly treat karta hai.Non-technical stakeholders ke liye interpretable. MAE of 5.2 = average 5.2 units off.
RMSE
Root Mean Squared Error
$\sqrt{\frac1n\sum(y_i-\hat y_i)^2}$		Average squared errors ka square root. Large errors ko heavily penalize karta hai.Jab large errors catastrophic hon. 9 small errors + 1 huge error → RMSE spike.
$R^2$ Score
Coefficient of Determination		Relative scale: 0 to 1. Model ko baseline average guess se compare karta hai.0.85 = model 85% variance explain karta hai. Baseline ke upar improvement directly dikhata hai.

📌 $R^2$ ko detail mein Lecture 7 mein cover kiya gaya hai.

2. Business metric mapping

Software industry mein mathematical performance ko business value mein translate karna hi padta hai. Engineers ko technical results seedhe operational impacts se map karna hota hai.

Example

Agriculture mein RMSE ko 1.5 units kam karna → predicted crop failure mein 12% reduction → estimated ₹2,00,000 per field hectare ki lost revenue bachti hai.

Practice P7

Pick the right metric

ScenarioMetricWhy
(a) A medical prediction error of 100 units is catastrophic (fatal)RMSESquaring large errors ko disproportionately punish karti hai — exactly wahi behaviour jo hume chahiye jab ek bada miss fatal ho.
(b) A non-technical CEO asks "how much better is this model than random guessing?"$R^2$$R^2$ ek relative score hai jo mean-only baseline se compare karta hai — "kitna behtar" ka seedha jawab.
(c) A logistics team wants "on average, how many km off are our delivery estimates?"MAE"On average, how many units off" = literally MAE ki definition, aur original units mein interpretable.
△ Reflect 2

RMSE ko 1.5 units improve karna agricultural business ke liye valuable kyun hai?
Kyunki yield prediction hi poori downstream planning drive karti hai: kitna fertilizer khareedna hai, kitne storage silos book karne hain, kis price par forward contracts sign karne hain. Ek chhota sa prediction error bhi over-purchasing, spoilage ya missed contracts mein translate hota hai. 1.5 units ka RMSE reduction directly predicted crop failure ko 12% kam karta hai, jo ₹2,00,000 per hectare bachata hai. Yeh abstract statistical improvement nahi hai — yeh balance sheet par dikhta hai.

♦ Takeaway

MAE equal-penalty interpretation ke liye. RMSE jab large errors catastrophic hon. $R^2$ baseline ke against relative performance ke liye. Hamesha metrics ko business value mein translate karo.

11Post-Deployment (The Living System)

▷ Hook

Tum 2019 mein airline travel predict karne ke liye ek ML model deploy karte ho. 2020 mein ek global pandemic aa jaati hai. Tumhara model 2010–2019 ke data par trained tha. Kya wo abhi bhi accurate hai?

Model Drift

Traditional code hamesha identically chalta hai. ML models decay karte hain. Model Drift tab hota hai jab prediction accuracy girti hai kyunki real-world environment badal gaya hai, jisse original training insights outdated ho jaate hain.

Continuous production monitoring

  • Prometheus aur MLflow jaise tools background mein continuously chalte hain.
  • Ye incoming live data ke statistical distributions track karte hain.
  • Performance jaise hi acceptable baseline threshold ke neeche girti hai, ye engineering teams ko alert karte hain.

The retraining cycle

StrategyHow It WorksExample
Periodic RetrainingFixed schedule (monthly/quarterly), performance ki parwah kiye binaHar mahine ki 1 tareekh ko automatically retrain
Triggered RetrainingTab start hota hai jab monitoring accuracy ko threshold ke neeche detect kareAlert: accuracy 85% se neeche gir gayi → abhi retrain karo
