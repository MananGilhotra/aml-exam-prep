PART I · Why Feature Selection?

1More columns do not always mean more information

▷ Hook

Lecture 8 mein humne deliberately $x^2$ jaise features banaye taaki model ek curved pattern represent kar sake. Lecture 9 mein humne dekha ki extra flexibility bias kam kar sakti hai par variance badha bhi sakti hai. Ab hum complementary question poochte hain:

Jab ek dataset mein pehle se hi bohot saare columns hain, to kaunse columns rehne ke laayak hain?

2Feature Selection: the problem

Definitions

A feature is an input variable or column used by a model to predict a target. Feature selection is the process of choosing a smaller subset of relevant features while preserving, or ideally improving, performance on unseen data.

★ Key Insight

"Most important" ek absolute label nahi hai. Yeh depend karta hai: target, model, evaluation metric, sample, aur wo baaki features jo pehle se present hain.

2.1 Three kinds of feature behaviour ⭐

RedundantRepeats information already carried by another feature.CGPA_copy repeats CGPA.
IrrelevantVaries but does not carry a stable relationship with the target.Random_number may vary and still be useless.
♦ Takeaway

Feature selection redundant aur irrelevant inputs hataane ki koshish karta hai — bina genuinely useful signal discard kiye.

2.2 Feature selection is NOT feature transformation

3Why feature selection can improve learning

3.1 Generalization and the bias–variance connection

Zyada features model ki flexibility badhate hain. Jahan useful features bias kam karte hain, wahan irrelevant features model ko random noise fit karne par majboor karte hain — jisse variance badhta hai aur validation performance bigadti hai.

Classroom question

Das features add karne ke baad training error ghat gaya, par validation error badh gaya. Kya naye features ne model ko stable pattern seekhne mein help ki?
Nahi. Training error hamesha girta hai jab features add hote hain (👉 Lecture 4). Validation error ka badhna classic high-variance / overfitting signature hai — naye features ne signal nahi, noise add kiya. 👉 Lecture 9

3.2 Computation, memory, and interpretability

  • Efficiency: Smaller matrices, faster training/prediction, lower memory use.
  • Explainability: Kam features wala model explain karna easier hai.
  • Stability: Redundant inputs hataane se multicollinearity kam hoti hai, jisse linear coefficients zyada stable bante hain (👉 Lecture 8).
  • Multicollinearity pure prediction ke liye coefficient interpretation se kam damaging ho sakti hai, par wo phir bhi redundancy aur instability represent karti hai.

4The two feature-selection families

Filter methods

Simple statistical checks (jaise correlation) use karke features ko kisi bhi model ke train hone se pehle screen karte hain.

Wrapper methods

Actual predictive model ko alag-alag feature subsets par train karke dekhte hain ki kaunsa subset best perform karta hai.

★ A third family (worth knowing)

Embedded methods — selection training ke dauraan automatically hoti hai. Sabse common example L1 (Lasso) Regularization hai, jo useless features ke coefficients ko exactly zero par push kar deta hai. Tree-based models ke Feature Importance Scores bhi embedded hain. (👉 Lecture 2, Phase 6)

PART II · Filter Methods — screen features before the final model

5Filter intuition and Duplicate Removal

▷ Hook

Ek filter method ek admission gate ki tarah act karta hai. Wo ek feature ko ek simple structural ya statistical rule se evaluate karta hai aur decide karta hai ki wo modeling stage mein enter karne ka haqdaar hai ya nahi. Final predictive model is screening step ke dauraan repeatedly train nahi hota.

Kuch filters target use nahi karte; doosre ek feature ko target se compare karte hain.

Agar do columns har row mein exactly same value contain karte hain, to wo same information provide karte hain:

$$f_a = f_b \qquad \text{for every observation}$$

Dono rakhne se evidence ka doosra independent source nahi banta. Stipend example mein, CGPA aur CGPA_copy exact duplicates hain. Ek linear model ke liye, dono retain karna perfect multicollinearity bhi create karta hai, to unke individual contributions uniquely separate nahi kiye ja sakte.

Which copy should be kept?
  • Wo column rakho jiska naam clearer aur zyada meaningful hai.
  • Wo column prefer karo jisme kam missing ya corrupted values hain.
  • Wo feature prefer karo jise prediction time par collect karna easier aur cheaper hai.
  • Check karo ki apparent duplicate koi data-leakage column to nahi hai jo target known hone ke baad banaya gaya ho.
♦ Takeaway

Duplicate removal safe hai kyunki wo repeated information hataata hai, unique information nahi.

6Variance Threshold

▷ Hook

Ek feature jo observations ke across barely badalta hai, wo ek observation ko doosre se distinguish nahi kar sakta. Simplest case ek constant column hai: agar har student ki same value hai, to wo feature explain hi nahi kar sakta ki stipends alag kyun hain.

Variance of feature $f_j$$$\operatorname{Var}(f_j) = \frac{1}{n}\sum_{i=1}^{n}(x_{ij} - \bar x_j)^2$$

Choose a threshold $\tau$. Remove the feature when:

$$\operatorname{Var}(f_j) < \tau$$

The threshold is a modeling choice / hyperparameter, not a universal constant. (A common starting value is $\tau = 0.1$, but it must be validated.)

Worked

What a variance filter sees

Feature valuesVarianceWhat the filter seesWhat must be remembered
Constant: $[5,5,5,5,5]$0No variation; remove.A constant feature cannot separate observations.
Rare binary: $[0,0,0,0,1]$0.16Low variation; may be removed for a high $\tau$.A rare event can still be strongly predictive.
Identifier-like: $[101,102,103,104,105]$2Moderate variation; may be kept.An identifier can vary greatly and still be irrelevant.
Verify these three variances yourself

$[5,5,5,5,5]$: $\bar x = 5$; all deviations are 0; $\operatorname{Var} = 0$.

$[0,0,0,0,1]$: $\bar x = 0.2$; deviations $-0.2$ (×4) and $+0.8$; squares $0.04$ (×4) and $0.64$; sum $= 0.16+0.64 = 0.80$; $\operatorname{Var} = 0.80/5 = \mathbf{0.16}$.

$[101,\dots,105]$: $\bar x = 103$; deviations $-2,-1,0,1,2$; squares $4,1,0,1,4$; sum $= 10$; $\operatorname{Var} = 10/5 = \mathbf{2}$.

Limitations of a variance threshold ⭐
  • A high-variance feature may have no relationship with the target.
  • A low-variance feature may be highly predictive, especially for a rare but important condition.
  • The method ignores combinations and interactions among features.
  • The threshold depends on units, scaling choices, and context.

7Pearson Correlation Between Each Feature and the Target

▷ Hook

Variance batati hai ki ek feature badalta hai ya nahi. Wo yeh nahi batati ki feature target ke saath-saath badalta hai ya nahi. Numerical feature aur numerical target ke liye, Pearson correlation ek linear relationship ki strength aur direction measure karta hai.

Pearson correlation$$r_{jY} = \frac{\sum_i (x_{ij} - \bar x_j)(y_i - \bar y)}{\sqrt{\sum_i (x_{ij} - \bar x_j)^2\ \sum_i (y_i - \bar y)^2}}$$
  • $r$ close to $+1$: strong positive linear relationship.
  • $r$ close to $-1$: strong negative linear relationship.
  • $r$ close to $0$: weak linear relationship — not necessarily no relationship.

An illustrative rule is:

$$\text{Remove } f_j \text{ when } |r_{jY}| < 0.30$$

The value 0.30 is only an illustration; the threshold must be validated through model performance.

FeatureIllustrative $r$ with stipendDecision under $|r| \ge 0.30$Caution
CGPA0.68KeepStrong linear association in this sample.
IQ score0.18RemoveCould still help jointly or nonlinearly.
Number of projects0.57KeepUseful linear association.
Attendance0.09RemoveThreshold decision must be validated.
Student_ID−0.02RemoveLarge variance did not imply relevance.
7.1 · The nonlinear counterexample

A feature with $r = 0$ that perfectly determines $y$

Let $y = x^2$ for symmetric values of $x$:

$x$−2−1012
$y = x^2$41014
  1. Calculate $\bar x$ and $\bar y$ $$\bar x = \frac{-2-1+0+1+2}{5} = \mathbf{0}, \qquad \bar y = \frac{4+1+0+1+4}{5} = \frac{10}{5} = \mathbf{2}$$
  2. Compute the numerator $\sum(x_i - \bar x)(y_i - \bar y)$ $$\sum(x_i - 0)(y_i - 2) = (-2)(+2) + (-1)(-1) + (0)(-2) + (1)(-1) + (2)(2)$$ $$= -4 + 1 + 0 - 1 + 4 = \mathbf{0}$$
  3. Therefore $$r_{XY} = \frac{0}{\sqrt{(\cdot)(\cdot)}} = \mathbf{0}$$
    A $|r| \ge 0.30$ filter would REMOVE $x$ — even though $y$ is completely determined by $x$.
★ Key Insight

Ek feature ki Pearson correlation zero ho sakti hai aur phir bhi wo ek nonlinear relationship ke through perfectly predictive ho sakta hai. Pearson correlation sirf linear association measure karta hai.

Limitations of target correlation ⭐
  • It can miss nonlinear relationships (the $y = x^2$ case above).
  • It evaluates one feature at a time and can miss useful interactions.
  • It is sensitive to outliers.
  • Its threshold is context-dependent.
  • Correlation does not establish causation or future stability.

8Correlation Among Input Features

Pichla calculation har feature ko $y$ se compare karta tha. Correlation input features ko ek dusre se bhi compare kar sakti hai taaki redundancy detect ho aur multicollinearity kam ho.

Maan lo $f_1$ aur $f_2$ ki correlation $0.95$ hai. Wo bohot similar linear information carry karte hain. Practical rule: ek representative feature rakho, par choice deliberate honi chahiye.

How to choose which correlated feature to keep
  • Prefer the feature with the stronger validated relationship with the target.
  • Prefer the feature with less missingness and measurement noise.
  • Prefer the feature that is easier to interpret and collect.
  • Use domain knowledge before removing intentionally engineered terms.
△ WARNING — DO NOT APPLY PAIRWISE RULES BLINDLY

Features $x$ aur $x^2$ correlated ho sakte hain, par dono ki zaroorat ho sakti hai curvature represent karne ke liye. Ek high input correlation automatically prove nahi karti ki ek engineered feature remove kar dena chahiye. Final decision ko validation performance se check karo.

8.1 Filter-method summary

StrengthsLimitations
Simple, fast, and scalable.Usually ignores interactions among multiple features.
Can remove obvious problems before expensive modeling.A statistical score may not match the needs of the final model.

♦ Takeaway

Filter methods efficient hain, par wo directly yeh poochte hi nahi ki chosen model features ke kisi particular combination ke saath better perform karta hai ya nahi.

PART III · Wrapper Methods — let model performance judge the subset

9The wrapper idea and the wrapper loop

▷ Hook

Ek feature akele weak lag sakta hai aur doosre ke saath pair hone par useful ban sakta hai. Conversely, do individually useful features saath use hone par redundant ho sakte hain. Wrapper methods whole subsets ko us predictive model ke saath evaluate karte hain jo hum actually use karne wale hain.

  • Filters features ko ek-ek karke evaluate karte hain, ignore karte hue ki wo saath kaise kaam karte hain.
  • Filters features ke beech useful interactions miss kar sakte hain.
  • Ek simple statistical score tumhare complex model ke seekhne ke tareeke se align nahi kar sakta.
★ Key Insight

Ek wrapper method model training aur validation ko feature-selection process ke "around" wrap kar deta hai.

9.1 The wrapper loop

  1. Generate a candidate subset of features.
  2. Train the chosen model on that subset.
  3. Evaluate the subset using validation data or cross-validation.
  4. Generate the next candidate subset according to the search strategy.
  5. Stop when the search is complete or a stopping rule is met.
△ WARNING — USE CROSS-VALIDATED SCORES

Jab features add kiye jaate hain, training data par model ki performance almost hamesha better lagegi, chahe naye features useless hon. Ek subset ko truly evaluate karne ke liye tumhe ek cross-validated score use karna hi padega. Cross-validation model ko us data par test karta hai jo usne training ke dauraan nahi dekha, jisse bohot zyada honest estimate milta hai.

11.6 Computational advantage and greedy limitation

For $p = 4$, backward elimination fits:

$$1 + 4 + 3 + 2 = \mathbf{10}\ \text{candidate models}$$

instead of all 15 nonempty subsets. In general:

$$1 + p + (p-1) + \cdots + 2 = \frac{p(p+1)}{2}$$

This grows quadratically rather than exponentially, although every score may still require several cross-validation fits.

△ WARNING — GREEDY SEARCH

Backward elimination har stage par ek locally best decision leta hai. Ek baar feature remove ho gaya, to use kabhi reconsider nahi kiya jaata. Isliye yeh method ek globally best combination miss kar sakta hai jisme koi pehle discard kiya gaya feature ho.

Dono greedy hain aur alag paths explore karte hain — isliye wo legitimately different subsets select kar sakte hain. Yeh bug nahi hai; yeh greedy search ki expected property hai.

12.6 When forward or backward selection is more natural ⭐

Use FORWARD when…

$p$ is large and the desired final subset is small; for example, keep about 10 of 100 features.

Reason: you never have to fit a 100-feature model at all.

Use BACKWARD when…

The model can fit all $p$ features and the desired final subset retains most of them; for example, keep about 90 of 100.

Reason: you reach the answer in only ~10 removal stages.

Both are greedy and model-specific, so they can select different subsets (as we just saw).

13.1 Practical method-choice rules ⭐

  • Start with filters when $p$ is very large or when obvious duplicates and near-constant columns exist.
  • Use a wrapper when the feature count is manageable, model-specific performance matters, and computational budget is available.
  • Combine methods when useful: apply simple filters first, then run a wrapper on the reduced set.
  • Always compare the selected-feature pipeline with an all-feature baseline using the same validation procedure.

14Validation Discipline: Avoid the Leakage Trap ⭐

▷ Hook

Feature selection tumhare model ko sikhaane ka hissa hai. Yeh ek harmless step NAHI hai jo tum data properly split karne se pehle kar sakte ho.

△ WARNING — THE LEAKAGE TRAP

Wrong: Poore dataset use karke apne features select karna, aur phir data ko training aur validation sets mein split karna. Agar tum aisa karte ho, to tumhara model feature selection step ke dauraan validation data par "peek" kar chuka hai. Ise data leakage kehte hain, aur isse tumhari performance falsely optimistic dikhegi.

Right: Har cross-validation fold ke andar, feature selection sirf us fold ke training portion se perform karo. Phir untouched validation portion par evaluate karo.

The final test set should never be used to choose which features to keep. It is used exactly once, at the very end, to estimate how well your final pipeline will perform in the real world.

15The Selected Subset Is Not Universal

Ek selected feature set ek particular experimental design se supported hota hai; wo ek permanent truth nahi hai.

  • Change the target, and relevant features can change.
  • Change the model, and the useful subset can change.
  • Change the evaluation metric, and the preferred subset can change.
  • Change the sample, and unstable selection procedures may choose different features.

Therefore, report the selected features together with the dataset, target, model, metric, and validation design that supported them.

16End-to-End Feature-Selection Workflow ⭐

Step 1Define the target, evaluation metric, and final modeling goal.
Step 2Create the train–validation–test structure before learning selection rules.
Step 3Remove exact duplicates and structurally unusable columns.
Step 4Use simple filters for obvious low-information or redundant inputs, while checking their limitations.
Step 5Use a wrapper when model-specific subset evaluation is needed and computationally feasible.
Step 6Choose thresholds, feature counts, and stopping rules inside cross-validation.
Step 7Compare with the all-feature baseline; prefer the simpler model only when generalization is maintained or improved.
Step 8Evaluate once on the untouched test set and report the final feature set with the method used to obtain it.
♦ Takeaway

Feature selection tabhi successful hai jab smaller representation useful signal preserve kare aur complete predictive pipeline ki reliability, efficiency ya interpretability improve kare.

16.1 Closing synthesis

  1. More features can add signal, but they can also add redundancy, noise, computation, and variance.
  2. Filter methods screen quickly using structural or statistical rules, but usually miss interactions.
  3. Wrapper methods judge candidate subsets using the chosen model, but repeated fitting is expensive and greedy searches can miss the global optimum.
  4. Selection must occur inside validation; the test set remains untouched until every decision is fixed.

Comprehensive Challenge

  1. (a) Diagnose the pipeline. A student: (1) computes correlations using the entire dataset; (2) keeps the top five features; (3) runs five-fold cross-validation using those five columns; (4) reports the mean validation score. Is the reported score trustworthy?
    No.

    The problem: Step 1 mein correlations poore dataset se compute hui — including har wo row jo baad mein CV validation folds mein jaayegi. Isliye feature-selection decision already un rows ko dekh chuki hai. CV ka "unseen data" ab genuinely unseen nahi hai. Yeh data leakage hai aur reported score optimistically biased hai.

    Corrected procedure: selection ko CV loop ke andar move karo. Har fold ke liye: (i) us fold ka training portion lo; (ii) sirf us portion se correlations compute karo; (iii) top five features select karo; (iv) us training portion par model fit karo; (v) untouched validation portion par evaluate karo. Phir paanch fold scores average karo. Alag folds alag features select kar sakte hain — yeh bilkul theek hai, aur yeh khud procedure ki stability ka ek useful signal hai.

  5. (e) Two subsets have nearly the same cross-validated performance. One uses 18 features and the other uses 7. Which would you normally prefer, and what could justify the larger subset?
    Normally prefer the 7-feature subset.

    Why: Equal performance par, simpler model jeetta hai — faster training and inference, lower memory, less multicollinearity, easier to explain, fewer columns to collect and monitor in production, aur lower variance.

    What could justify the 18-feature set: (i) agar wo extra features distribution shift ke against robustness dete hain (7-feature model ek narrow signal par over-reliant ho sakta hai); (ii) agar folds ke across uska performance zyada stable hai (kam std deviation), jo suggest karta hai ki 7-feature ka result ek lucky split tha; (iii) agar kuch extra features regulatory ya monitoring reasons se retain karne hote hain.

  6. (f) Why can the selected features change when the target, model, metric, or sample changes?

    Kyunki "relevance" koi feature ki intrinsic property nahi hai — wo ek relationship hai.

    • Target badla: feature ka jis cheez se relate karna tha, wo hi badal gayi.
    • Model badla: linear model ko explicit interaction terms chahiye; ek tree unhe khud construct kar leta hai, to alag columns mangega.
    • Metric badla: RMSE ke liye optimal subset recall ke liye optimal subset se alag ho sakta hai.
    • Sample badla: greedy search paths chhote data changes par sensitive hote hain — ek stage par 0.81 vs 0.83 flip hone se poora baaki path badal jaata hai.

⚠ Common Mistakes

GaltiSahi Baat
Poore dataset par features select karke phir split karnaData leakage. Selection CV ke andar, sirf training fold se.
"High variance = useful feature"Student_ID ki variance huge hai par $r = -0.02$. Variance necessary hai, sufficient nahi.
"$r = 0$ means no relationship"$y = x^2$ par $r = 0$ hota hai jabki $y$ $x$ se completely determined hai. Pearson sirf linear measure karta hai.
"Smallest subset is always best"Sirf tab jab performance maintained ho. Ties par simplicity jeetti hai — losses par nahi.
Training scores par subsets compare karnaFeatures add karne par training score hamesha better lagta hai. Cross-validated scores use karo.
$x$ aur $x^2$ correlated dekh ke squared term drop karnaWo mathematically correlated honge hi. Curvature ki ability chali jaayegi. Validate karo.
Forward aur backward ka same answer expect karnaDono greedy hain aur alag paths explore karte hain — different subsets normal hai.
