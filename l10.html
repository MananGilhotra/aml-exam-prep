More columns do not mean more information. Filter methods screen features with cheap statistical checks before any model is trained (duplicates, variance, correlation) — but they miss interactions. PART I · Why Feature Selection?

1More columns do not always mean more information

▷ Hook

In Lecture 8 we deliberately built features such as $x^2$ so the model could represent a curved pattern. In Lecture 9 we saw that extra flexibility can reduce bias but can also increase variance. Now we ask the complementary question:

When a dataset already has many columns, which columns deserve to stay?

2Feature Selection: the problem

Definitions

A feature is an input variable or column used by a model to predict a target. Feature selection is the process of choosing a smaller subset of relevant features while preserving, or ideally improving, performance on unseen data.

★ Key Insight

"Most important" is not an absolute label. It depends on the target, the model, the evaluation metric, the sample, and which other features are already present.

2.1 Three kinds of feature behaviour ⭐

RedundantRepeats information already carried by another feature.CGPA_copy repeats CGPA.
IrrelevantVaries but does not carry a stable relationship with the target.Random_number may vary and still be useless.
♦ Takeaway

Feature selection tries to remove redundant and irrelevant inputs — without discarding genuinely useful signal.

2.2 Feature selection is NOT feature transformation

Feature transformationFeature selection

Can both appear in one pipeline?Yes. First build meaningful candidates, then select among them.

3Why feature selection can improve learning

3.1 Generalization and the bias–variance connection

More features increase the model's flexibility. Where useful features reduce bias, irrelevant features force the model to fit random noise — which raises variance and degrades validation performance.

Classroom question

After adding ten features the training error fell, but the validation error rose. Did the new features help the model learn a stable pattern?
No. Training error always falls when features are added (👉 Lecture 4). A rise in validation error is the classic high-variance / overfitting signature — the new features added noise, not signal. 👉 Lecture 9

3.2 Computation, memory, and interpretability

  • Efficiency: Smaller matrices, faster training/prediction, lower memory use.
  • Explainability: a model with fewer features is easier to explain.
  • Stability: removing redundant inputs reduces multicollinearity, which makes linear coefficients more stable (👉 Lecture 8).
  • Multicollinearity can be less damaging for pure prediction than for coefficient interpretation, but it still represents redundancy and instability.

4The two feature-selection families

Filter methods

Use simple statistical checks (such as correlation) to screen features before any model is trained.

Wrapper methods

Train the actual predictive model on different feature subsets and see which subset performs best.

★ A third family (worth knowing)

Embedded methods — selection happens automatically during training. The most common example is L1 (Lasso) Regularization, which pushes the coefficients of useless features to exactly zero. The Feature Importance Scores of tree-based models are embedded too. (👉 Lecture 2, Phase 6)

PART II · Filter Methods — screen features before the final model

5Filter intuition and Duplicate Removal

▷ Hook

A filter method acts like an admission gate. It evaluates a feature against a simple structural or statistical rule and decides whether it deserves to enter the modeling stage. The final predictive model is not trained repeatedly during this screening step.

Some filters do not use the target at all; others compare a feature against the target.

If two columns contain exactly the same value in every row, they provide the same information:

$$f_a = f_b \qquad \text{for every observation}$$

Keeping both does not create a second independent source of evidence. In the stipend example, CGPA and CGPA_copy are exact duplicates. For a linear model, retaining both also creates perfect multicollinearity, so their individual contributions cannot be uniquely separated.

Which copy should be kept?
  • Keep the column whose name is clearer and more meaningful.
  • Prefer the column with fewer missing or corrupted values.
  • Prefer the feature that is easier and cheaper to collect at prediction time.
  • Check whether the apparent duplicate is actually a data-leakage column created after the target became known.
♦ Takeaway

Duplicate removal is safe because it removes repeated information, not unique information.

6Variance Threshold

▷ Hook

A feature that barely changes across observations cannot distinguish one observation from another. The simplest case is a constant column: if every student has the same value, that feature cannot possibly explain why the stipends differ.

Variance of feature $f_j$$$\operatorname{Var}(f_j) = \frac{1}{n}\sum_{i=1}^{n}(x_{ij} - \bar x_j)^2$$

Choose a threshold $\tau$. Remove the feature when:

$$\operatorname{Var}(f_j) < \tau$$

The threshold is a modeling choice / hyperparameter, not a universal constant. (A common starting value is $\tau = 0.1$, but it must be validated.)

Worked

What a variance filter sees

Feature valuesVarianceWhat the filter seesWhat must be remembered
Constant: $[5,5,5,5,5]$0No variation; remove.A constant feature cannot separate observations.
Rare binary: $[0,0,0,0,1]$0.16Low variation; may be removed for a high $\tau$.A rare event can still be strongly predictive.
Identifier-like: $[101,102,103,104,105]$2Moderate variation; may be kept.An identifier can vary greatly and still be irrelevant.
Verify these three variances yourself

$[5,5,5,5,5]$: $\bar x = 5$; all deviations are 0; $\operatorname{Var} = 0$.

$[0,0,0,0,1]$: $\bar x = 0.2$; deviations $-0.2$ (×4) and $+0.8$; squares $0.04$ (×4) and $0.64$; sum $= 0.16+0.64 = 0.80$; $\operatorname{Var} = 0.80/5 = \mathbf{0.16}$.

$[101,\dots,105]$: $\bar x = 103$; deviations $-2,-1,0,1,2$; squares $4,1,0,1,4$; sum $= 10$; $\operatorname{Var} = 10/5 = \mathbf{2}$.

Limitations of a variance threshold ⭐
  • A high-variance feature may have no relationship with the target.
  • A low-variance feature may be highly predictive, especially for a rare but important condition.
  • The method ignores combinations and interactions among features.
  • The threshold depends on units, scaling choices, and context.

7Pearson Correlation Between Each Feature and the Target

▷ Hook

Variance tells us whether a feature changes. It does not tell us whether the feature changes together with the target. For a numerical feature and a numerical target, Pearson correlation measures the strength and direction of a linear relationship.

Pearson correlation$$r_{jY} = \frac{\sum_i (x_{ij} - \bar x_j)(y_i - \bar y)}{\sqrt{\sum_i (x_{ij} - \bar x_j)^2\ \sum_i (y_i - \bar y)^2}}$$
  • $r$ close to $+1$: strong positive linear relationship.
  • $r$ close to $-1$: strong negative linear relationship.
  • $r$ close to $0$: weak linear relationship — not necessarily no relationship.

An illustrative rule is:

$$\text{Remove } f_j \text{ when } |r_{jY}| < 0.30$$

The value 0.30 is only an illustration; the threshold must be validated through model performance.

FeatureIllustrative $r$ with stipendDecision under $|r| \ge 0.30$Caution
CGPA0.68KeepStrong linear association in this sample.
IQ score0.18RemoveCould still help jointly or nonlinearly.
Number of projects0.57KeepUseful linear association.
Attendance0.09RemoveThreshold decision must be validated.
Student_ID−0.02RemoveLarge variance did not imply relevance.
7.1 · The nonlinear counterexample

A feature with $r = 0$ that perfectly determines $y$

Let $y = x^2$ for symmetric values of $x$:

$x$−2−1012
$y = x^2$41014
  1. Calculate $\bar x$ and $\bar y$ $$\bar x = \frac{-2-1+0+1+2}{5} = \mathbf{0}, \qquad \bar y = \frac{4+1+0+1+4}{5} = \frac{10}{5} = \mathbf{2}$$
  2. Compute the numerator $\sum(x_i - \bar x)(y_i - \bar y)$ $$\sum(x_i - 0)(y_i - 2) = (-2)(+2) + (-1)(-1) + (0)(-2) + (1)(-1) + (2)(2)$$ $$= -4 + 1 + 0 - 1 + 4 = \mathbf{0}$$
  3. Therefore $$r_{XY} = \frac{0}{\sqrt{(\cdot)(\cdot)}} = \mathbf{0}$$
    A $|r| \ge 0.30$ filter would REMOVE $x$ — even though $y$ is completely determined by $x$.
★ Key Insight

A feature can have zero Pearson correlation and still be perfectly predictive through a nonlinear relationship. Pearson correlation measures only linear association.

Limitations of target correlation ⭐
  • It can miss nonlinear relationships (the $y = x^2$ case above).
  • It evaluates one feature at a time and can miss useful interactions.
  • It is sensitive to outliers.
  • Its threshold is context-dependent.
  • Correlation does not establish causation or future stability.

8Correlation Among Input Features

The previous calculation compared each feature against $y$. Correlation can also compare input features against one another, to detect redundancy and reduce multicollinearity.

Suppose $f_1$ and $f_2$ have a correlation of $0.95$. They carry very similar linear information. Practical rule: keep one representative feature, but make the choice deliberately.

How to choose which correlated feature to keep
  • Prefer the feature with the stronger validated relationship with the target.
  • Prefer the feature with less missingness and measurement noise.
  • Prefer the feature that is easier to interpret and collect.
  • Use domain knowledge before removing intentionally engineered terms.
△ WARNING — DO NOT APPLY PAIRWISE RULES BLINDLY

The features $x$ and $x^2$ may be correlated, but both may be needed in order to represent curvature. A high input correlation does not automatically prove that an engineered feature should be removed. Check the final decision against validation performance.

8.1 Filter-method summary

StrengthsLimitations
Simple, fast, and scalable.Usually ignores interactions among multiple features.
Can remove obvious problems before expensive modeling.A statistical score may not match the needs of the final model.
Often model-independent and easy to explain.Threshold choice can be arbitrary or unstable.

Filter methods are efficient, but they never directly ask whether the chosen model performs better with some particular combination of features.

PART III · Wrapper Methods — let model performance judge the subset

9The wrapper idea and the wrapper loop

▷ Hook

A feature can look weak on its own and become useful when paired with another. Conversely, two individually useful features can be redundant when used together. Wrapper methods evaluate whole subsets with the predictive model we actually intend to use.

  • Filters evaluate features one at a time, ignoring how they work together.
  • Filters can miss useful interactions between features.
  • A simple statistical score may not align with how your complex model actually learns.
★ Key Insight

A wrapper method wraps model training and validation around the feature-selection process.

9.1 The wrapper loop

  1. Generate a candidate subset of features.
  2. Train the chosen model on that subset.
  3. Evaluate the subset using validation data or cross-validation.
  4. Generate the next candidate subset according to the search strategy.
  5. Stop when the search is complete or a stopping rule is met.
△ WARNING — USE CROSS-VALIDATED SCORES

When features are added, the model's performance on the training data will almost always look better, even if the new features are useless. To truly evaluate a subset you must use a cross-validated score. Cross-validation tests the model on data it did not see during training, which gives a far more honest estimate.

10Exhaustive Feature Selection

Exhaustive search evaluates every nonempty subset and chooses the one with the best validation score. Each of the $p$ features has two states: included or excluded. Therefore:

11.6 Computational advantage and greedy limitation

For $p = 4$, backward elimination fits:

$$1 + 4 + 3 + 2 = \mathbf{10}\ \text{candidate models}$$

instead of all 15 nonempty subsets. In general:

$$1 + p + (p-1) + \cdots + 2 = \frac{p(p+1)}{2}$$

This grows quadratically rather than exponentially, although every score may still require several cross-validation fits.

△ WARNING — GREEDY SEARCH

Backward elimination makes a locally best decision at each stage. Once a feature has been removed, it is never reconsidered. So this method can miss a globally best combination that includes a feature discarded earlier.

Forward selection does not simply keep adding features until all of them are used. Stop when an additional feature gives no meaningful validation improvement, or choose the best subset along the whole forward path.

Note — backward and forward disagreed!

Backward elimination picked $\{f_1, f_2, f_4\}$ (0.91). Forward selection picked $\{f_1, f_4, f_3\}$ (0.85). Both are greedy and explore different paths — so they can legitimately select different subsets. This is not a bug; it is an expected property of greedy search.

12.6 When forward or backward selection is more natural ⭐

Use FORWARD when…

$p$ is large and the desired final subset is small; for example, keep about 10 of 100 features.

Reason: you never have to fit a 100-feature model at all.

Use BACKWARD when…

The model can fit all $p$ features and the desired final subset retains most of them; for example, keep about 90 of 100.

Reason: you reach the answer in only ~10 removal stages.

Both are greedy and model-specific, so they can select different subsets (as we just saw).

13.1 Practical method-choice rules ⭐

  • Start with filters when $p$ is very large or when obvious duplicates and near-constant columns exist.
  • Use a wrapper when the feature count is manageable, model-specific performance matters, and computational budget is available.
  • Combine methods when useful: apply simple filters first, then run a wrapper on the reduced set.
  • Always compare the selected-feature pipeline with an all-feature baseline using the same validation procedure.

14Validation Discipline: Avoid the Leakage Trap ⭐

▷ Hook

Feature selection is part of teaching your model. It is NOT a harmless step you can do before splitting the data properly.

△ WARNING — THE LEAKAGE TRAP

Wrong: selecting your features using the whole dataset, and then splitting the data into training and validation sets. If you do that, your model has already "peeked" at the validation data during the feature-selection step. This is called data leakage, and it makes your performance look falsely optimistic.

Right: inside each cross-validation fold, perform feature selection using only the training portion of that fold. Then evaluate on the untouched validation portion.

The final test set should never be used to choose which features to keep. It is used exactly once, at the very end, to estimate how well your final pipeline will perform in the real world.

15The Selected Subset Is Not Universal

A selected feature set is supported by a particular experimental design; it is not a permanent truth.

  • Change the target, and relevant features can change.
  • Change the model, and the useful subset can change.
  • Change the evaluation metric, and the preferred subset can change.
  • Change the sample, and unstable selection procedures may choose different features.

Therefore, report the selected features together with the dataset, target, model, metric, and validation design that supported them.

16End-to-End Feature-Selection Workflow ⭐

Step 1Define the target, evaluation metric, and final modeling goal.
Step 2Create the train–validation–test structure before learning selection rules.
Step 3Remove exact duplicates and structurally unusable columns.
Step 4Use simple filters for obvious low-information or redundant inputs, while checking their limitations.
Step 5Use a wrapper when model-specific subset evaluation is needed and computationally feasible.
Step 6Choose thresholds, feature counts, and stopping rules inside cross-validation.
Step 7Compare with the all-feature baseline; prefer the simpler model only when generalization is maintained or improved.
Step 8Evaluate once on the untouched test set and report the final feature set with the method used to obtain it.
♦ Takeaway

Feature selection is successful only when the smaller representation preserves the useful signal and improves the reliability, efficiency or interpretability of the complete predictive pipeline.

16.1 Closing synthesis

  1. More features can add signal, but they can also add redundancy, noise, computation, and variance.
  2. Filter methods screen quickly using structural or statistical rules, but usually miss interactions.
  3. Wrapper methods judge candidate subsets using the chosen model, but repeated fitting is expensive and greedy searches can miss the global optimum.
  4. Selection must occur inside validation; the test set remains untouched until every decision is fixed.
Practice P4

Comprehensive Challenge

  1. (a) Diagnose the pipeline. A student: (1) computes correlations using the entire dataset; (2) keeps the top five features; (3) runs five-fold cross-validation using those five columns; (4) reports the mean validation score. Is the reported score trustworthy?
    No.

    The problem: in Step 1 the correlations were computed from the whole dataset — including every row that later lands in a CV validation fold. So the feature-selection decision has already seen those rows. The CV's "unseen data" is no longer genuinely unseen. This is data leakage, and the reported score is optimistically biased.

    Corrected procedure: move the selection inside the CV loop. For each fold: (i) take that fold's training portion; (ii) compute the correlations from that portion only; (iii) select the top five features; (iv) fit the model on that training portion; (v) evaluate on the untouched validation portion. Then average the five fold scores. Different folds may select different features — that is perfectly fine, and it is itself a useful signal about the stability of the procedure.

  5. (e) Two subsets have nearly the same cross-validated performance. One uses 18 features and the other uses 7. Which would you normally prefer, and what could justify the larger subset?
    Normally prefer the 7-feature subset.

    Why: at equal performance, the simpler model wins — faster training and inference, lower memory, less multicollinearity, easier to explain, fewer columns to collect and monitor in production, and lower variance.

    What could justify the 18-feature set: (i) if those extra features provide robustness against distribution shift (the 7-feature model may be over-reliant on one narrow signal); (ii) if its performance is more stable across folds (a smaller standard deviation), suggesting the 7-feature result was a lucky split; (iii) if some extra features must be retained for regulatory or monitoring reasons.

  6. (f) Why can the selected features change when the target, model, metric, or sample changes?

    Because "relevance" is not an intrinsic property of a feature — it is a relationship.

    • The target changed: the very thing the feature had to relate to is now different.
    • The model changed: a linear model needs explicit interaction terms; a tree constructs them itself, so it will want different columns.
    • The metric changed: the subset that is optimal for RMSE may differ from the subset that is optimal for recall.
    • The sample changed: greedy search paths are sensitive to small data changes — a 0.81 vs 0.83 flip at one stage changes the entire rest of the path.

⚠ Common Mistakes

GaltiSahi Baat
Selecting features on the whole dataset and then splittingData leakage. Selection goes inside CV, using the training fold only.
"High variance = useful feature"Student_ID has huge variance but $r = -0.02$. Variance is necessary, not sufficient.
"$r = 0$ means no relationship"For $y = x^2$, $r = 0$ even though $y$ is completely determined by $x$. Pearson measures only linear association.
"Smallest subset is always best"Only when performance is maintained. On ties, simplicity wins — not on losses.
Comparing subsets on training scoresAdding features always makes the training score look better. Use cross-validated scores.
Dropping the squared term because $x$ and $x^2$ look correlatedThey are bound to be mathematically correlated. You would lose the ability to model curvature. Validate instead.
Expecting forward and backward search to give the same answerBoth are greedy and explore different paths — different subsets are normal.
Tuning the correlation threshold on the test setThe test set is never part of a decision. Once, at the very end.
