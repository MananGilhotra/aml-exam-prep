P1Defining the Problem (The Foundation)

▷ Hook

Tumhari music streaming company kehti hai: "Users leaving hain! Isko fix karne ke liye ek AI banao!" Agar tum abhi laptop kholke linear regression code karna shuru kar do, to tum almost guaranteed fail kyun ho?

The five-step blueprint

Ek algorithm guess nahi kar sakta ki tumhari business ko kya chahiye. Phase 1 ek messy human problem ko explicit mathematical framework mein translate karta hai — paanch steps se:

StepWhat You DoExample
1. Understand the ProblemExact friction point isolate karoUsers canceling premium subscriptions = churn
2. Set Quantifiable GoalsEk measurable target define karo"Reduce churn by 10% over two quarters"
3. Assess ML FeasibilityPoocho: kya hume ML chahiye? Kya data hai?Kya ek SQL query kaam kar degi? Agar haan, to ML skip karo.
4. Identify ConstraintsBudget, latency, privacy laws (GDPR)Predictions in <10 ms on a phone?
5. Stakeholder AlignmentPMs, devs, execs success par agree kareinShared definition of "success"

Blueprint in action

✗ Vague

"We want to improve our online retail store."

✓ Rigorous

"Using historical clickstreams and purchase data, predict which users will stop shopping within 3 months."

★ Key Insight

Ek poorly defined problem ek bad algorithm se zyada time waste karta hai. Tum "make it better" optimize nahi kar sakte — algorithm ko ek number chahiye jise minimize kare.

△ Reflect 2 — Is more data always better?

Tumhara scraper 100k reviews collect karta hai par 40% bot-generated spam hai.
Answer: Nahi. Quality > quantity. 40% garbage rows model ko spam patterns ko genuine signal samajhna sikha denge, distribution shift kar denge aur bias inject karenge. 60k clean reviews 100k dirty reviews se behtar hain. Yeh seedha "Garbage In = Garbage Out" ka case hai.

P3Exploratory Data Analysis (EDA)

▷ Hook

Tumhari company tumhe 500,000 customer records deti hai. Sabse pehla kaam kya? Agar tumne kaha "train a model" — ruko. Doctor patient ko examine kiye bina treatment prescribe nahi karta.

EDA diagnostic stage hai. Yeh raw data ko preprocessing se pehle actionable insights mein transform karta hai.

EDA checklist — 7 goals

GoalWhat You Check
1. Dataset StructureRows, columns, data types, feature names
2. Missing ValuesKaunse columns? Kitne? Random ya systematic?
3. OutliersExtreme values (data error? fraud? rare case?)
4. DuplicatesRepeated rows from collection/merging errors
5. DistributionsNormal (bell) vs Skewed (left/right)
6. RelationshipsCorrelation, dependency, redundant features
7. Class Imbalance95% Non-Fraud vs 5% Fraud → accuracy lies

△ Reflect 3 — The 95% accuracy trap

Dataset 95% Class A aur 5% Class B hai. Model har baar A predict karta hai → 95% accuracy. Useful hai?
Nahi. Class B ka recall = 0 hai (0 out of all actual B pakde gaye). Model ne kuch seekha hi nahi — sirf majority class guess kar raha hai. Yeh class imbalance hai; accuracy yahan jhoot bolti hai. Precision, recall, F1 ya confusion matrix dekho (👉 Lecture 7).

♦ Takeaway

EDA first, algorithm later. Structure samjho → issues dhoondo → patterns visualize karo → phir preprocess karo.

P4Data Preprocessing (The Real Engineering Work)

▷ Hook

Textbooks mein data hamesha clean hota hai. Real world mein? Messy, biased, incomplete. Kya ek sophisticated algorithm khud self-correct karke garbage ignore kar dega? Nahi. Garbage In, Garbage Out.

Algorithms data ko numbers ke matrices ke roop mein dekhte hain. Missing value? Equation break. Ek feature millions mein, doosra single digits mein? Bada feature maths ko overwhelm kar dega. Preprocessing ek clean numerical matrix banata hai.

Step 3: Feature scaling ⭐

Jab ek feature 1–5 (bedrooms) range karta hai aur doosra $\$20{,}000$–$\$500{,}000$ (income), to distance-based algorithms (KNN, SVM) aur gradient descent bade feature se dominate ho jaate hain. Scaling ise fix karta hai.

TechniqueFormulaUse WhenRisk
A. Min-Max
(Normalization)		 $X_{\text{scaled}} = \dfrac{X - X_{\min}}{X_{\max} - X_{\min}}$
Maps to $[0, 1]$		 Not Gaussian; neural nets; bounded ranges Ek outlier baaki sab ko 0 ke paas squash kar deta hai
B. Z-Score
(Standardization)		 $Z = \dfrac{X - \mu}{\sigma}$
Mean → 0, Std → 1		 Data Normal distribution follow karta hai Best tab jab features approximately Gaussian hon
C. Max Absolute $X_{\text{scaled}} = \dfrac{X}{\max(|X|)}$
Maps to $[-1, 1]$		 Sparse data (many zeros, e.g. bag-of-words) Zeros aur sign preserve karta hai
D. Robust $X_{\text{scaled}} = \dfrac{X - \text{Median}}{Q_3 - Q_1}$
$\text{IQR} = Q_3 - Q_1$		 Heavy outliers jinhe tum drop nahi kar sakte Mean/std ignore karta hai; median + middle 50% use karta hai
★ Key Insight

Min-Max outliers ke prati sensitive hai (ek extreme value sab kuch squash kar deti hai). Z-Score normality assume karta hai. Robust Scaling tumhara safety net hai jab outliers unavoidable hon.

Numerical A

Min-Max Scaling · $X = [10, 20, 30, 40, 50]$

  1. Formula likho $$X_{\text{scaled}} = \frac{X - X_{\min}}{X_{\max} - X_{\min}}$$
  2. Min aur Max nikalo $X_{\min} = 10$,   $X_{\max} = 50$  ⟹  denominator $= 50 - 10 = 40$
  3. Har value substitute karo $$X = 10:\quad \frac{10-10}{40} = \frac{0}{40} = \mathbf{0}$$ $$X = 30:\quad \frac{30-10}{40} = \frac{20}{40} = \mathbf{0.5}$$ $$X = 50:\quad \frac{50-10}{40} = \frac{40}{40} = \mathbf{1}$$
  4. Sanity check
    Min hamesha → 0, Max hamesha → 1. Poora vector: $[0,\ 0.25,\ 0.5,\ 0.75,\ 1]$ ✓
Numerical B

Z-Score Standardization · $X = [2, 4, 6, 8, 10]$

  1. Mean nikalo $$\mu = \frac{2+4+6+8+10}{5} = \frac{30}{5} = \mathbf{6}$$
  2. Deviations aur unke squares
    $X$246810
    $X - \mu$−4−20+2+4
    $(X-\mu)^2$1640416
  3. Standard deviation $$\sigma^2 = \frac{16+4+0+4+16}{5} = \frac{40}{5} = 8 \quad\Rightarrow\quad \sigma = \sqrt{8} \approx 2.828$$
  4. Har value ka $z$ $$X=2:\ z = \frac{2-6}{\sqrt 8} = \frac{-4}{2.828} = \mathbf{-1.414}$$ $$X=6:\ z = \frac{6-6}{\sqrt 8} = \mathbf{0}$$ $$X=10:\ z = \frac{10-6}{\sqrt 8} = \frac{4}{2.828} = \mathbf{+1.414}$$
  5. Verify
    Mean value ($X=6$) hamesha $z=0$ deti hai. Symmetric data → symmetric z-scores. ✓
Numerical C

Robust Scaling — full walkthrough · $X = [100, 150, 200, 250, 50000]$

  1. Sort karo $[100,\ 150,\ 200,\ 250,\ 50000]$ — already sorted.
  2. Median ($Q_2$) 5 values → middle (3rd) value. $\;Q_2 = \mathbf{200}$
  3. $Q_1$ = median of lower half $[100, 150]$ $$Q_1 = \frac{100 + 150}{2} = \mathbf{125}$$
  4. $Q_3$ = median of upper half $[250, 50000]$ $$Q_3 = \frac{250 + 50000}{2} = \frac{50250}{2} = \mathbf{25125}$$
  5. IQR $$\text{IQR} = Q_3 - Q_1 = 25125 - 125 = \mathbf{25000}$$
  6. Scale $X = 100$ $$\frac{100 - 200}{25000} = \frac{-100}{25000} = \mathbf{-0.004}$$
  7. Scale $X = 50000$ $$\frac{50000 - 200}{25000} = \frac{49800}{25000} = \mathbf{1.992}$$
  8. Outlier (50000) ne scale kyun nahi toda?
    Kyunki Robust Scaling median aur IQR use karta hai, min/max ya mean/std nahi. Outlier median ko barely hilaata hai, aur IQR sirf middle 50% ko dekhta hai. Isliye normal values ($100, 150, 200$) apas mein distinguishable rehti hain ($-0.004$, $-0.002$, $0$) — collapse nahi hotin.
Compare: wahi data Min-Max se

$X_{\max} - X_{\min} = 50000 - 100 = 49900$. Ab: $100 \to 0$, $150 \to 0.001$, $200 \to 0.002$, $250 \to 0.003$, $50000 \to 1$. Chaaron normal values 0 ke paas squash ho gayin — model unke beech farak hi nahi dekh paayega. Yehi Reflect 4 ka answer hai.

Step 4: Categorical encoding ⭐

Agar hum Red=0, Green=1, Blue=2 map karein, to model sochta hai Blue > Green > Red, aur (Red+Blue)/2 = Green. Yeh ek mathematical lie hai. Encoding carefully choose karo.

EncodingHowSafe ForDanger
LabelHar category ko unique integer
Red=0, Blue=1, Green=2		Binary targets (Spam=1/0); tree-based models (split karte hain, distance nahi)Distance-based models (KNN, SVM) ke liye false order imply karta hai
OrdinalControlled rank mapping
Low=0, Med=1, High=2		Natural rank wali categories; tree + linear modelsGalat, agar categories actually unordered hon
One-Hot$N$ binary columns (1 = present)
Red→[0,0,1], Blue→[1,0,0]		Unordered nominal data with few unique valuesCurse of Dimensionality jab bohot categories hon
BinaryInteger → binary digits, $\log_2 N$ columns mein splitMany categories; space-efficient alternativeOne-Hot se lower dimensional representation (kuch interpretability jaati hai)

One-Hot Encoding — Red / Blue / Green

3 categories → 3 columns. Har row mein exactly ek 1. Koi false ordering nahi — sab categories mathematically equidistant hain.

Worked

Binary Encoding — Blue=1→01, Red=2→10, Green=3→11

InputBit_0Bit_1

3 categories → sirf 2 columns (One-Hot ko 3 chahiye the).

★ Key Insight — the scaling argument

One-Hot: 3 categories = 3 columns. Binary: 3 categories = 2 columns. Aur 1000 categories ke liye? One-Hot = 1000 columns; Binary $\approx \lceil\log_2 1000\rceil = $ 10 columns. Yahi curse of dimensionality ka jawab hai.

△ Reflect 5 — Label Encoding KNN ko kyun mislead karta hai par Decision Tree ko nahi?

KNN distances compute karta hai. Agar Red=0, Blue=1, Green=2, to KNN ke liye $|Red - Green| = 2$ par $|Red - Blue| = 1$ — yaani Red, Blue se "zyada similar" hai Green ke comparison mein. Yeh completely fabricated hai.
Decision Tree splits karta hai, distance nahi. Wo poochta hai "Is value $\le 0.5$?" — jo effectively Red ko {Blue, Green} se separate karta hai. Tree kisi bhi threshold par split karke categories recover kar sakta hai; magnitudes ka use hi nahi hota. Isliye tree-based models ke liye Label Encoding safe hai.

♦ Takeaway

Ordinal ranked categories ke liye · One-Hot nominal with few values · Binary nominal with many · Label sirf tree models ya binary targets ke liye.
