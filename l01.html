P1Defining the Problem (The Foundation)

▷ Hook

Your music streaming company says: "Users are leaving! Build an AI to fix it!" If you open your laptop right now and start coding a linear regression, why are you almost guaranteed to fail?

The five-step blueprint

An algorithm cannot guess what your business needs. Phase 1 translates a messy human problem into an explicit mathematical framework — in five steps:

StepWhat You DoExample
1. Understand the ProblemIsolate the exact friction pointUsers canceling premium subscriptions = churn
2. Set Quantifiable GoalsDefine a measurable target"Reduce churn by 10% over two quarters"
3. Assess ML FeasibilityAsk: do we even need ML? Do we have the data?Would a SQL query do the job? If yes, skip ML entirely.
4. Identify ConstraintsBudget, latency, privacy laws (GDPR)Predictions in <10 ms on a phone?
5. Stakeholder AlignmentPMs, devs and execs agree on what success meansShared definition of "success"

Blueprint in action

✗ Vague

"We want to improve our online retail store."

✓ Rigorous

"Using historical clickstreams and purchase data, predict which users will stop shopping within 3 months."

★ Key Insight

A poorly defined problem wastes more time than a bad algorithm. You cannot optimise "make it better" — the algorithm needs a number it can minimise.

Practice P1

Rewrite each vague request as a rigorous ML problem statement

  1. (a) "Our hospital needs better patient care."

    → "Using admission vitals, lab panels and past visit history, predict the probability that a discharged patient will be re-admitted within 30 days, so that high-risk patients get a follow-up call. Target: reduce 30-day readmissions by 8% in 2 quarters. Constraint: prediction must be available at discharge time (<1 min), and must respect patient-data privacy rules."

    Har blueprint step present: friction point, quantified goal, feasibility (data exists), constraint, stakeholder-visible success.
  2. (b) "Make our email system smarter."

    → "Using the email payload (subject, body text, sender reputation), classify each incoming email as spam or not-spam. Target: recall ≥ 98% on spam with false-positive rate < 0.1%. Constraint: classification must complete in <50 ms per email at 10k emails/sec."

    Task type clear (binary classification), metric clear, latency constraint clear.
△ Reflect 1

A company has excellent customer data, but does not have permission to use that data to train an ML model. Which phase of the lifecycle does this problem belong to?
Answer: Step 4 — Identify Constraints (operational / legal constraints, e.g. GDPR). This should be caught in Phase 1 itself, not after data collection.

♦ Takeaway

Until you have a quantified target, confirmed data access and stakeholder agreement — don't touch the code.

△ Reflect 2 — Is more data always better?

Your scraper collects 100k reviews but 40% of them are bot-generated spam.
Answer: no. Quality beats quantity. Those 40% garbage rows will teach the model to treat spam patterns as genuine signal, shift the distribution, and inject bias. 60k clean reviews beat 100k dirty ones. This is exactly the "Garbage In = Garbage Out" case.

♦ Takeaway

Before writing a single line of code: know your sources, know the structure, know the feature types.

P3Exploratory Data Analysis (EDA)

▷ Hook

Your company hands you 500,000 customer records. What is the very first thing you do? If you said "train a model" — stop. A doctor does not prescribe treatment without examining the patient first.

EDA is the diagnostic stage. It turns raw data into actionable insight before preprocessing begins.

EDA checklist — 7 goals

GoalWhat You Check
1. Dataset StructureRows, columns, data types, feature names
2. Missing ValuesKaunse columns? Kitne? Random ya systematic?
3. OutliersExtreme values (data error? fraud? rare case?)
4. DuplicatesRepeated rows from collection/merging errors
5. DistributionsNormal (bell) vs Skewed (left/right)
6. RelationshipsCorrelation, dependency, redundant features
7. Class Imbalance95% Non-Fraud vs 5% Fraud → accuracy lies

△ Reflect 3 — The 95% accuracy trap

A dataset is 95% Class A and 5% Class B. The model predicts A every single time → 95% accuracy. Is that useful?
No. Class B has recall = 0 (none of the actual B cases were caught). The model learned nothing — it is just guessing the majority class. This is class imbalance, and accuracy lies here. Look at precision, recall, F1 or the confusion matrix instead (👉 Lecture 7).

♦ Takeaway

EDA first, algorithm later. Understand the structure → hunt for issues → visualise the patterns → then preprocess.

P4Data Preprocessing (The Real Engineering Work)

▷ Hook

In textbooks the data is always clean. In the real world? Messy, biased, incomplete. Will a sophisticated algorithm self-correct and ignore the garbage on its own? No. Garbage In, Garbage Out.

Algorithms see data as matrices of numbers. A missing value? The equation breaks. One feature in the millions and another in single digits? The bigger one overwhelms the maths. Preprocessing produces a clean numerical matrix.

Step 1: Handling missing values

StrategyActionWhen to UseDanger
DeletionDrop the rows or columns<1–2% missing; or a column that is >80% emptyInformation is discarded and bias gets introduced
ImputationFill with mean/median (numerical) or mode (categorical)Moderate missingnessCan introduce artificial patterns

Step 2: Handling inconsistent data

TypeIssueFix
Mixed UnitsWeight recorded in both kg and lbsStandardise onto a single unit
Typos'Californa', 'California', 'CA'Regex / Levenshtein distance matching
DuplicatesSame record twice loggedRemove the duplicate records
Inconsistent LabelsYes, Y, True, 1 — all mean "yes"Map them all to a single label format

Step 3: Feature scaling ⭐

When one feature ranges 1–5 (bedrooms) and another ranges $\$20{,}000$–$\$500{,}000$ (income), distance-based algorithms (KNN, SVM) and gradient descent get dominated by the bigger feature. Scaling fixes this.

TechniqueFormulaUse WhenRisk
A. Min-Max
(Normalization)		 $X_{\text{scaled}} = \dfrac{X - X_{\min}}{X_{\max} - X_{\min}}$
Maps to $[0, 1]$		 Not Gaussian; neural nets; bounded ranges A single outlier squashes everything else near 0
B. Z-Score
(Standardization)		 $Z = \dfrac{X - \mu}{\sigma}$
Mean → 0, Std → 1		 The data follows a Normal distribution Best tab jab features approximately Gaussian hon
C. Max Absolute $X_{\text{scaled}} = \dfrac{X}{\max(|X|)}$
Maps to $[-1, 1]$		 Sparse data (many zeros, e.g. bag-of-words) Preserves zeros and sign
D. Robust $X_{\text{scaled}} = \dfrac{X - \text{Median}}{Q_3 - Q_1}$
$\text{IQR} = Q_3 - Q_1$		 Heavy outliers that you cannot drop Ignores mean/std; uses the median + middle 50%
★ Key Insight

Min-Max is sensitive to outliers (one extreme value squashes everything). Z-Score assumes normality. Robust Scaling is your safety net when outliers are unavoidable.

Numerical A

Min-Max Scaling · $X = [10, 20, 30, 40, 50]$

  1. Formula likho $$X_{\text{scaled}} = \frac{X - X_{\min}}{X_{\max} - X_{\min}}$$
  2. Find Min and Max $X_{\min} = 10$,   $X_{\max} = 50$  ⟹  denominator $= 50 - 10 = 40$
  3. Substitute each value $$X = 10:\quad \frac{10-10}{40} = \frac{0}{40} = \mathbf{0}$$ $$X = 30:\quad \frac{30-10}{40} = \frac{20}{40} = \mathbf{0.5}$$ $$X = 50:\quad \frac{50-10}{40} = \frac{40}{40} = \mathbf{1}$$
  4. Sanity check
    Min always → 0, Max always → 1. The full vector: $[0,\ 0.25,\ 0.5,\ 0.75,\ 1]$ ✓
Numerical B

Z-Score Standardization · $X = [2, 4, 6, 8, 10]$

  1. Find the mean $$\mu = \frac{2+4+6+8+10}{5} = \frac{30}{5} = \mathbf{6}$$
  2. Deviations aur unke squares
    $X$246810
    $X - \mu$−4−20+2+4
    $(X-\mu)^2$1640416
  3. Standard deviation $$\sigma^2 = \frac{16+4+0+4+16}{5} = \frac{40}{5} = 8 \quad\Rightarrow\quad \sigma = \sqrt{8} \approx 2.828$$
  4. The $z$ for each value $$X=2:\ z = \frac{2-6}{\sqrt 8} = \frac{-4}{2.828} = \mathbf{-1.414}$$ $$X=6:\ z = \frac{6-6}{\sqrt 8} = \mathbf{0}$$ $$X=10:\ z = \frac{10-6}{\sqrt 8} = \frac{4}{2.828} = \mathbf{+1.414}$$
  5. Verify
    The mean value ($X=6$) always gives $z=0$. Symmetric data → symmetric z-scores. ✓
Numerical C

Robust Scaling — full walkthrough · $X = [100, 150, 200, 250, 50000]$

  1. Sort $[100,\ 150,\ 200,\ 250,\ 50000]$ — already sorted.
  2. Median ($Q_2$) 5 values → middle (3rd) value. $\;Q_2 = \mathbf{200}$
  3. $Q_1$ = median of lower half $[100, 150]$ $$Q_1 = \frac{100 + 150}{2} = \mathbf{125}$$
  4. $Q_3$ = median of upper half $[250, 50000]$ $$Q_3 = \frac{250 + 50000}{2} = \frac{50250}{2} = \mathbf{25125}$$
  5. IQR $$\text{IQR} = Q_3 - Q_1 = 25125 - 125 = \mathbf{25000}$$
  6. Scale $X = 100$ $$\frac{100 - 200}{25000} = \frac{-100}{25000} = \mathbf{-0.004}$$
  7. Scale $X = 50000$ $$\frac{50000 - 200}{25000} = \frac{49800}{25000} = \mathbf{1.992}$$
  8. Why did the outlier (50000) not break the scale?
    Because Robust Scaling uses the median and IQR, not min/max or mean/std. The outlier barely moves the median, and the IQR only looks at the middle 50%. So the normal values ($100, 150, 200$) stay distinguishable from each other ($-0.004$, $-0.002$, $0$) instead of collapsing together.
Compare: the same data under Min-Max

$X_{\max} - X_{\min} = 50000 - 100 = 49900$. Now: $100 \to 0$, $150 \to 0.001$, $200 \to 0.002$, $250 \to 0.003$, $50000 \to 1$. All four normal values got squashed near 0 — the model can no longer tell them apart. That is the answer to Reflect 4.

Step 4: Categorical encoding ⭐

If we map Red=0, Green=1, Blue=2, the model believes Blue > Green > Red, and that (Red+Blue)/2 = Green. That is a mathematical lie. Choose the encoding carefully.

EncodingHowSafe ForDanger
LabelA unique integer per category
Red=0, Blue=1, Green=2		Binary targets (Spam=1/0); tree-based models (they split, they don't measure distance)Implies a false order for distance-based models (KNN, SVM)
OrdinalControlled rank mapping
Low=0, Med=1, High=2		Categories with a natural rank; tree + linear modelsWrong if the categories are actually unordered
One-Hot$N$ binary columns (1 = present)
Red→[0,0,1], Blue→[1,0,0]		Unordered nominal data with few unique valuesThe Curse of Dimensionality when there are many categories
BinaryInteger → binary digits, split across $\log_2 N$ columnsMany categories; a space-efficient alternativeA lower-dimensional representation than One-Hot (you lose some interpretability)
Worked

One-Hot Encoding — Red / Blue / Green

Green010

3 categories → 3 columns. Exactly one 1 per row. No false ordering — all categories are mathematically equidistant.

Worked

★ Key Insight — the scaling argument

One-Hot: 3 categories = 3 columns. Binary: 3 categories = 2 columns. And for 1000 categories? One-Hot = 1000 columns; Binary $\approx \lceil\log_2 1000\rceil = $ 10 columns. That is the answer to the curse of dimensionality.

△ Reflect 5 — why does Label Encoding mislead KNN but not a Decision Tree?

KNN computes distances. If Red=0, Blue=1, Green=2, then for KNN $|Red - Green| = 2$ while $|Red - Blue| = 1$ — meaning Red is "more similar" to Blue than to Green. That is completely fabricated.
A Decision Tree splits, it doesn't measure distance. It asks "Is value $\le 0.5$?" — which effectively separates Red from {Blue, Green}. A tree can recover the categories by splitting at any threshold; the magnitudes are never used. That is why Label Encoding is safe for tree-based models.

♦ Takeaway

Ordinal for ranked categories · One-Hot for nominal with few values · Binary for nominal with many · Label only for tree models or binary targets.

⚠ Common Mistakes

GaltiSahi Baat
Treating a PIN code as a numerical featureA PIN code is Categorical (Nominal) — arithmetic on it is meaningless.
