Batch Gradient Descent
for Multiple Linear Regression

When closed-form OLS will not work — reaching the optimal parameters through iterative optimization.

⏱ ~32 min📐 Gradient derivation 🧮 Full epoch by hand✓ 10 MCQs
⚡ Ek Line Mein

OLS is exact, but it costs $O(m^3)$ and fails outright when $\mathbf X^\top\mathbf X$ is singular. The idea behind Gradient Descent is simple: find the slope of the loss, and take a small step in the opposite direction — over and over. The rule: $\boldsymbol\theta_{\text{new}} = \boldsymbol\theta_{\text{old}} - \alpha\nabla L$. For MSE, $\nabla L = \frac{2}{m}\mathbf X^\top(\mathbf X\boldsymbol\theta - \mathbf y)$. It is called "Batch" kyunki every update uses the entire dataset.

1Why OLS is not enough

▷ Hook

In Lecture 4 we did something elegant. We set the gradient of the loss to zero and solved for $\boldsymbol\theta$ directly. The result was exact. So why do we need another method at all?

The closed-form OLS solution$$\boldsymbol\theta^* = (\mathbf X^\top\mathbf X)^{-1}\mathbf X^\top\mathbf y$$

There is no trial and error here, no epochs, no learning rate. But there are two major limitations:

Limitation 1 · Computational cost

$\mathbf X$ has $m+1$ columns (including the intercept), so $\mathbf X^\top\mathbf X$ has size $(m+1)\times(m+1)$. Inverting that matrix directly costs approximately:

$$O(m^3)$$

If the model has 5 features, the inversion is trivial. If it has millions of features, the inversion becomes computationally impossible.

Limitation 2 · Invertibility & numerical stability

The formula only works when $\mathbf X^\top\mathbf X$ is invertible (i.e. its determinant is non-zero). That requires the columns of $\mathbf X$ to be linearly independent.

★ Key Insight

If two features are exact duplicates, or one feature is a linear combination of another, $\mathbf X^\top\mathbf X$ becomes singular — the inverse simply does not exist.

We need a method that never explicitly inverts $\mathbf X^\top\mathbf X$. That method is Batch Gradient Descent.

Practice P1

Scenario evaluation — OLS or Gradient Descent?

  1. Scenario A: 10,000 rows but only 3 features (Age, Income, Credit Score)
    Use OLS.

    Why: $m = 3$, so $\mathbf X^\top\mathbf X$ is only $4\times4$. Inversion costs $\approx 4^3 = 64$ operations — nothing. The number of rows ($n = 10{,}000$) doesn't affect the inversion cost at all (that depends only on $m$). The closed form gives an exact answer in one step, with no learning rate to tune.

  2. Scenario B: Computer-vision regression with 50,000 image-derived features
    Use Gradient Descent.

    Why: $m^3 = (5\times10^4)^3 = 1.25\times10^{14}$ operations — that would take days, and storing a $50{,}001 \times 50{,}001$ matrix needs ~20 GB of RAM. GD costs only $O(nm)$ per iteration and never forms an inverse.

  3. Scenario C: A junior engineer includes both Price_USD and Price_Cents (where Price_Cents = 100 × Price_USD)

    What specific error will OLS throw?

    A singular matrix error — $\det(\mathbf X^\top\mathbf X) = 0$, so $(\mathbf X^\top\mathbf X)^{-1}$ does not exist (in NumPy: LinAlgError: Singular matrix).

    Can Batch Gradient Descent still run on this data? Yes.
    GD never inverts any matrix — it only computes $\mathbf X^\top(\mathbf X\boldsymbol\theta - \mathbf y)$, which is always defined. It will converge, with one nuance: since infinitely many $\boldsymbol\theta$ give the same minimum loss, GD settles on one of them (depending on initialisation). The predictions will be reliable; the individual coefficients $\theta_{\text{USD}}$ and $\theta_{\text{cents}}$ will not be worth interpreting.

2Introduction to Gradient Descent

▷ Hook

The objective of Gradient Descent is to reach the minimum of the loss function: the parameter values where prediction error is smallest.

Single-variable case

For a function $f(x)$, the derivative $f'(x)$ tells us the slope:

  • If $f'(x) > 0$, the function increases as $x$ increases.
  • If $f'(x) < 0$, the function decreases as $x$ increases.

If we want to decrease the function, we have to move in the opposite direction to the derivative.

Multivariable case

For a function $f(\theta_0, \theta_1, \dots, \theta_m)$, the gradient is the vector of all its partial derivatives:

$$\nabla f = \begin{bmatrix}\dfrac{\partial f}{\partial\theta_0}\\[4pt] \dfrac{\partial f}{\partial\theta_1}\\[2pt] \vdots\\[2pt] \dfrac{\partial f}{\partial\theta_m}\end{bmatrix}$$
Worked example

Computing a gradient and taking one step

Let $f(x, y) = x^2 + y^2$.

  1. Compute the gradient $$\nabla f = \begin{bmatrix}\partial f/\partial x\\ \partial f/\partial y\end{bmatrix} = \begin{bmatrix}2x\\ 2y\end{bmatrix}$$
  2. Evaluate at the point $(3, 4)$ $$\nabla f\big|_{(3,4)} = \begin{bmatrix}2(3)\\ 2(4)\end{bmatrix} = \begin{bmatrix}6\\ 8\end{bmatrix}$$
  3. Take one step with $\alpha = 0.1$ $$\boldsymbol\theta_{\text{new}} = \begin{bmatrix}3\\4\end{bmatrix} - 0.1\begin{bmatrix}6\\8\end{bmatrix} = \begin{bmatrix}3 - 0.6\\ 4 - 0.8\end{bmatrix} = \begin{bmatrix}\mathbf{2.4}\\ \mathbf{3.2}\end{bmatrix}$$
    Moved closer to the minimum at $(0,0)$ ✓
  4. Now try $\alpha = 1$ — watch what breaks $$\boldsymbol\theta_{\text{new}} = \begin{bmatrix}3\\4\end{bmatrix} - 1\begin{bmatrix}6\\8\end{bmatrix} = \begin{bmatrix}\mathbf{-3}\\ \mathbf{-4}\end{bmatrix}$$
    Overshoot! We crossed the minimum and landed on the other side, at exactly the same distance. The value of $f$ didn't change at all ($9+16 = 25$ in both places). The next step takes us right back to $(3,4)$ — infinite oscillation.

    This is the exact mathematical demonstration of the "$\alpha$ too large" failure mode.

♦ Takeaway — the key geometric fact

The gradient points in the direction of steepest increase of the function. Therefore the negative gradient points in the direction of steepest decrease.

For a convex, bowl-shaped loss, repeatedly following the negative gradient takes us to the same global minimum from any starting point — provided the learning rate is appropriate.

The update rule

Single parameter$$\theta_{\text{new}} = \theta_{\text{old}} - \alpha\left.\frac{dL}{d\theta}\right|_{\theta_{\text{old}}}$$

Here $\alpha > 0$ is the learning rate: a user-chosen hyperparameter controlling the size of each step. Gradient Descent applies this rule iteratively — old becomes new, the gradient is recomputed, and the process continues until convergence (when the loss or the parameters change negligibly).

Coordinate-wise, for MLR with $m$ features ($m+1$ parameters)$$\theta_{j,\text{new}} = \theta_{j,\text{old}} - \alpha\left.\frac{\partial L}{\partial\theta_j}\right|_{\boldsymbol\theta_{\text{old}}} \qquad\text{for } j = 0, 1, \dots, m$$
△ Warning — SIMULTANEOUS UPDATE

All partial derivatives must be computed from the OLD value of $\boldsymbol\theta$, and all parameters must be updated simultaneously. Don't update $\theta_0$ and then use the new $\theta_0$ to compute the derivative for $\theta_1$.

Vector form$$\boxed{\;\boldsymbol\theta_{\text{new}} = \boldsymbol\theta_{\text{old}} - \alpha\,\nabla L(\boldsymbol\theta_{\text{old}})\;}$$
  • $\boldsymbol\theta$ — the full parameter vector
  • $\nabla L$ — the vector of all partial derivatives
  • $\alpha$ — the learning rate
  • The minus sign appears because the gradient points uphill, but we want to go downhill

Parameter initialization

  • For the convex loss functions used in Linear Regression and Logistic Regression, initialise $\boldsymbol\theta_{\text{old}}$ as the zero vector.
  • For non-convex Neural Network losses, parameters are initialised randomly (covered in the parallel Deep Learning course).

Effect of the learning rate on convergence

Derive the vectorized update rule

  1. 1. Stack the old parameters into a vector $\boldsymbol\theta$ $$\boldsymbol\theta_{\text{old}} = \begin{bmatrix}\theta_0\\ \theta_1\\ \vdots\\ \theta_m\end{bmatrix}$$
  2. 2. Stack all the partial derivatives into the gradient vector $\nabla L$ $$\nabla L = \begin{bmatrix}\partial L/\partial\theta_0\\ \partial L/\partial\theta_1\\ \vdots\\ \partial L/\partial\theta_m\end{bmatrix}$$
  3. 3. Write the final simultaneous vector update equation
    $\boldsymbol\theta_{\text{new}} = \boldsymbol\theta_{\text{old}} - \alpha\,\nabla L(\boldsymbol\theta_{\text{old}})$

3Deriving the Batch GD update for MSE ⭐

▷ Hook

Now let's make the loss definition, the gradient and the update rule mathematically consistent for Mean Squared Error.

MSE loss (matrix form)$$L(\boldsymbol\theta) = \frac{1}{m}(\mathbf X\boldsymbol\theta - \mathbf y)^\top(\mathbf X\boldsymbol\theta - \mathbf y) \qquad\text{equivalently}\qquad L(\boldsymbol\theta) = \frac{1}{m}\|\mathbf X\boldsymbol\theta - \mathbf y\|_2^2$$

Note: here $m$ = the number of training examples (this worksheet's notation). The feature count is denoted $d$ where needed.

Practice P4 · Derivation

Compute the gradient step by step

  1. Step 1 — Expand the loss function $$L(\boldsymbol\theta) = \frac{1}{m}\left[(\boldsymbol\theta^\top\mathbf X^\top - \mathbf y^\top)(\mathbf X\boldsymbol\theta - \mathbf y)\right]$$ $$L(\boldsymbol\theta) = \frac{1}{m}\left[\,\mathbf y^\top\mathbf y \;-\; 2\,\mathbf y^\top\mathbf X\boldsymbol\theta \;+\; \boldsymbol\theta^\top\mathbf X^\top\mathbf X\boldsymbol\theta\,\right]$$

    (Same three-term expansion as Lecture 4, with the two middle scalars combined.)

  2. Step 2 — Differentiate with respect to $\boldsymbol\theta$

    Recall the three identities:

    $$\frac{\partial}{\partial\boldsymbol\theta}(\mathbf y^\top\mathbf y) = \mathbf 0, \qquad \frac{\partial}{\partial\boldsymbol\theta}(-2\,\mathbf y^\top\mathbf X\boldsymbol\theta) = -2\,\mathbf X^\top\mathbf y, \qquad \frac{\partial}{\partial\boldsymbol\theta}(\boldsymbol\theta^\top\mathbf X^\top\mathbf X\boldsymbol\theta) = 2\,\mathbf X^\top\mathbf X\boldsymbol\theta$$ $$\nabla L = \frac{1}{m}\left[\mathbf 0 \;-\; 2\,\mathbf X^\top\mathbf y \;+\; 2\,\mathbf X^\top\mathbf X\boldsymbol\theta\right]$$
  3. Step 3 — Factor out the 2 and $\mathbf X^\top$
    The MSE gradient$$\boxed{\;\nabla L = \frac{2}{m}\,\mathbf X^\top(\mathbf X\boldsymbol\theta - \mathbf y)\;}$$
  4. Step 4 — Plug into the update rule
    Batch Gradient Descent update rule$$\boxed{\;\boldsymbol\theta := \boldsymbol\theta - \alpha\,\frac{2}{m}\,\mathbf X^\top(\mathbf X\boldsymbol\theta - \mathbf y)\;}$$
★ Key Insight — why is it called "Batch"?

Because the gradient uses the entire matrix $\mathbf X$ and the entire target vector $\mathbf y$. Every single training example contributes to every single update step.

Instructor note — the missing factor of 2

Some textbooks define the loss like this:

$$L(\boldsymbol\theta) = \frac{1}{2m}\|\mathbf X\boldsymbol\theta - \mathbf y\|_2^2$$

With that convention the factor of 2 disappears from the gradient (since $\frac{1}{2}\cdot 2 = 1$), and the update becomes $\boldsymbol\theta := \boldsymbol\theta - \alpha\frac{1}{m}\mathbf X^\top(\mathbf X\boldsymbol\theta - \mathbf y)$. In this lecture we use the actual MSE definition, so the factor 2 stays. In an exam, check which convention the question uses.

  3.   4. 3. Why was the update for $\theta_2$ (attendance) so much larger than $\theta_1$ (hours) in Epoch 1? What preprocessing step fixes this?

    The $j$-th component of the gradient is $\sum_i x_{ij}\,e_i$ — meaning it scales with the magnitude of feature $j$. Attendance values are $60$–$90$ while hours are $2$–$6$; a ratio of roughly $15$–$20\times$. So $\theta_2$'s gradient ($-8533$) is ~18× bigger than $\theta_1$'s ($-473$) — not because attendance is more important, only because its numbers are bigger.

    The practical damage: a single $\alpha$ cannot serve both. An $\alpha$ that is safe for $\theta_2$ is painfully slow for $\theta_1$; one that suits $\theta_1$ makes $\theta_2$ oscillate — exactly what we saw in Epoch 2 above (residuals flipping from negative to positive).

    Fix: feature scaling — apply standardisation ($z = \frac{x - \mu}{\sigma}$) or Min-Max scaling to both features, so they land in comparable ranges. 👉 Lecture 1 · Feature Scaling
★ Key Insight

Feature scaling is essential before applying Gradient Descent. Putting features on comparable scales stops a large-magnitude feature from dominating the gradient, and usually makes convergence faster and more stable.

5Epochs and the full training loop

▷ Hook

What we did above was one update. But training a model means repeating that update many times. Let's name the process carefully.

Epoch

In Batch Gradient Descent, one epoch means one complete pass over the full training dataset and one full-dataset gradient update.

Training loop — 7 steps

  1. Initialise parameters. For this convex Linear Regression loss, set $\boldsymbol\theta = \mathbf 0$. Neural Networks use random initialisation.
  2. Choose the number of epochs.
  3. Compute predictions. $\hat{\mathbf y} = \mathbf X\boldsymbol\theta$
  4. Compute residuals. $\mathbf X\boldsymbol\theta - \mathbf y$
  5. Compute the gradient. $\nabla L = \frac{2}{m}\mathbf X^\top(\mathbf X\boldsymbol\theta - \mathbf y)$
  6. Update parameters. $\boldsymbol\theta := \boldsymbol\theta - \alpha\nabla L$
  7. Repeat for the chosen number of epochs.
Practice P5

Epoch trivia

If the NST dataset has 3 students and we train for 100 epochs with Batch Gradient Descent, how many times does the model use the full dataset to compute a gradient?

100 times.

Reasoning: in BGD, one epoch = one complete pass = exactly one full-dataset gradient computation and exactly one parameter update. 100 epochs ⟹ 100 gradient computations ⟹ 100 parameter updates. (Contrast with SGD, where 100 epochs $\times$ 3 samples = 300 updates. 👉 Lecture 6)

♦ Takeaway

Gradient Descent is a general optimisation algorithm, not something limited to Linear Regression. It can optimise any differentiable loss function, simply by repeatedly moving the parameters in the negative-gradient direction.

6Learning rate, hyperparameter tuning, and trade-offs

The learning rate $\alpha$ is a hyperparameter. We choose it before training — gradient descent never learns it. It controls how big each step is.

Case 1 · $\alpha$ too small

The loss decreases, but very slowly. The model is heading in the right direction, but every step is tiny.

Case 2 · $\alpha$ too large

The loss may oscillate or diverge. The direction may be locally downhill, but the step is so big that the algorithm overshoots the minimum.

Case 3 · $\alpha$ well chosen

The loss drops quickly at first and then gradually flattens out near the minimum.

Hyperparameter tuning — how to actually pick $\alpha$

To find the best $\alpha$ we pick candidate values (e.g. $0.1, 0.01, 0.001$), train the model separately with each one, and track the loss on a held-out validation set. (The test set is reserved for final evaluation, not for repeatedly selecting settings.)

What is validation loss?

Validation loss is the average prediction error on examples that were not used to update $\boldsymbol\theta$. For a validation set of $m_{\text{val}}$ examples:

$$L_{\text{val}} = \frac{1}{m_{\text{val}}}\sum_{i=1}^{m_{\text{val}}}(y_i - \hat y_i)^2$$

Step-by-step tuning process

  1. Split the available development data into training and validation sets; keep the test set untouched.
  2. Choose candidate learning rates on a logarithmic scale, such as $0.1, 0.01, 0.001$.
  3. Start every candidate run from the same zero vector and train for the same epoch budget.
  4. Record both training loss and validation loss after every epoch.
  5. Reject any candidate that diverges or oscillates severely.
  6. Compare the best validation loss reached by each remaining candidate.
  7. Select the learning rate with the lowest validation loss — because it produced the smallest error on unseen validation data — then evaluate the final chosen setup once on the test set.

Advantages of Batch Gradient Descent

  • It uses the full dataset for every gradient computation, so the update direction is stable.
  • For a convex loss like linear regression's MSE, it can converge to the global minimum with an appropriate learning rate.
  • It avoids computing $(\mathbf X^\top\mathbf X)^{-1}$ explicitly.
  • It still runs when the inverse-based closed-form formula fails because $\mathbf X^\top\mathbf X$ is singular.

Disadvantages of Batch Gradient Descent

  • Every epoch requires a full pass over the entire dataset. (100,000 rows? All 100,000 for each single update.)
  • It can be slow when the dataset is very large.
  • The whole dataset usually has to be available to compute the full batch gradient efficiently.
  • Poor learning-rate choices can make training extremely slow or unstable.
